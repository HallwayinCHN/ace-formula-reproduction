## FORMULAS & CALCULATIONS

[calc-00001] helpful=6 harmful=0 :: Balance of Trade = Exports - Imports. When exports equal imports, the balance is zero. Always convert units consistently (e.g., millions to full numbers) before subtracting.
[calc-00002] helpful=0 harmful=0 :: In Black-Scholes option pricing, use high-precision values for the standard normal CDF N(d1) and N(d2) (e.g., from a computational tool or table with at least 6 decimal places). Avoid rounding intermediate results; carry full precision through to the final call/put price, then round only the final answer to the required decimal place. This prevents small CDF rounding errors from shifting the final answer across a rounding threshold (e.g., 6.9345 vs 6.935).
[calc-00003] helpful=6 harmful=0 :: When a problem asks for a floating point number (e.g., '5 million should be 5000000.0'), express rates and returns as decimals, not percentages. For CAPM: Expected Return = risk-free rate + beta × (expected market rate - risk-free rate), all as decimals. Compute the decimal result, then apply any rounding instruction (e.g., 'round to nearest hundredth') to that decimal. Example: 0.01 + 1.5 × (0.04 - 0.01) = 0.055, which rounds to 0.06.
[calc-00005] helpful=0 harmful=0 :: When a question asks for the effect on a rate (e.g., unemployment rate, interest rate) and the answer format is a plain number, compute the change as a decimal but then convert to percentage points by multiplying by 100. For example, if the change in unemployment is 16,000 and the labor force is 400,000, the decimal change is 0.04, which converts to 4.0 percentage points. Provide 4.0 as the final answer, not 0.04. This convention overrides the general rule for floating point numbers when the quantity is explicitly a rate change.
[calc-00006] helpful=1 harmful=0 :: Sortino Ratio = (R_p - R_f) / σ_d, where R_p is portfolio return, R_f is risk-free rate, and σ_d is downside deviation. Convert all percentages to decimals before computing (e.g., 6% = 0.06, 1.5% = 0.015, 3.5% = 0.035). Compute excess return, divide by downside deviation, and round only the final result as instructed.
[calc-00007] helpful=1 harmful=0 :: Free Cash Flow (FCF) = Operating Cash Flow - Capital Expenditures. Extract both values from the problem, subtract, and present the result as a plain floating point number (e.g., 16000.0) when the answer format requires it.
[calc-00008] helpful=0 harmful=0 :: Debt Service Coverage Ratio (DSCR or DSR) = Net Operating Income / Total Debt Service. Substitute the given values, divide, and round only the final result to the required precision (e.g., nearest hundredth). Ensure both numerator and denominator are in the same units.
[calc-00009] helpful=0 harmful=0 :: Enterprise Value (EV) = Market Cap + Total Debt - Cash and Cash Equivalents. EV/EBITDA = EV / EBITDA. Compute EV first, then divide by EBITDA, and round only the final result as instructed. Numerical equivalence matters more than trailing zeros in decimal formatting (e.g., 7.00 is equivalent to 7.0).
[calc-00010] helpful=0 harmful=0 :: Treynor Ratio = (Portfolio Return - Risk-Free Rate) / Beta. Convert all percentages to decimals before computing (e.g., 14% = 0.14, 1% = 0.01). Compute excess return, divide by beta, and round only the final result as instructed (e.g., to nearest hundredth).
[calc-00012] helpful=3 harmful=2 :: When a question asks for a margin or rate (e.g., Net Profit Margin, Gross Margin, Return on Sales) as a 'plain floating point number', the expected answer is often the percentage value (e.g., 5.0 for 5%), not the decimal fraction (0.05). After computing the ratio (Net Profit / Revenue), multiply by 100 to convert to percentage points, then output that number. Example: Net Profit Margin = 25000/500000 = 0.05; multiply by 100 to get 5.0, and output 5.0. This convention applies specifically to margin/rate questions and overrides the general decimal rule for floating point numbers.
[calc-00014] helpful=0 harmful=0 :: Return on Assets (ROA) = Net Income / Total Assets. When the answer format is a plain floating point number and the question asks for a return or rate, multiply the ratio by 100 to express as a percentage (e.g., 78,000 / 1,300,000 = 0.06; multiply by 100 to get 6.0). This aligns with the convention for margin/rate questions (calc-00012, err-00013).
[calc-00015] helpful=1 harmful=0 :: GDP (Expenditure Approach) = Consumption + Investment + Government Spending + (Exports - Imports). Compute net exports as Exports - Imports (can be negative). Sum all components. When values are given in billions, convert the final result to a full number by multiplying by 1,000,000,000 (e.g., 640 billion = 640,000,000,000.0).
[calc-00016] helpful=0 harmful=0 :: Effective Annual Rate (EAR) = (1 + r/m)^m - 1, where r is the nominal annual rate as a decimal and m is the number of compounding periods per year. Convert the nominal rate to decimal first (e.g., 2% = 0.02), divide by m, compound for one year, and subtract 1. Unless a percentage is explicitly requested, keep the final EAR as a decimal and apply any rounding instruction to that decimal (e.g., 0.020184... rounded to nearest hundredth = 0.02).
[calc-00017] helpful=1 harmful=0 :: Dividend Yield = Annual Dividend per Share / Price per Share. When the answer format is a plain floating point number and the question does not explicitly ask for a percentage, express the yield as a decimal (e.g., 6/60 = 0.1, output 0.1). Do NOT multiply by 100. The margin/rate conversion rule (calc-00012, err-00013) does not apply to dividend yield; only convert to percentage if the question explicitly requests it.
[calc-00019] helpful=1 harmful=0 :: Jensen's Alpha = R_i - [R_f + β_i × (R_m - R_f)], where R_i is the actual portfolio return, R_f is the risk-free rate, R_m is the market return, and β_i is the portfolio beta. Convert all percentages to decimals before computing. First calculate the expected return using CAPM: R_f + β_i × (R_m - R_f). Then subtract this expected return from the actual return. Round the final alpha to the required precision (e.g., nearest hundredth) and keep it as a decimal unless a percentage is explicitly requested.
[calc-00020] helpful=1 harmful=0 :: Market Capitalization = Shares Outstanding × Price per Share. Convert shares from millions to full numbers (e.g., 5 million = 5,000,000.0) before multiplying. Present the result as a floating point number (e.g., 275000000.0) when the answer format requires it.
[calc-00021] helpful=1 harmful=0 :: P/E Ratio = Market Value per Share / Earnings per Share. Substitute the given values directly, perform the division, and round only the final result as instructed (e.g., $35 / $3.5 = 10.0). Ensure both numerator and denominator are per-share values in the same currency units.
[calc-00022] helpful=2 harmful=0 :: Earnings Per Share (EPS) = (Net Income - Preferred Dividends) / Average Shares Outstanding. Always subtract preferred dividends from net income to find earnings available to common shareholders before dividing by average shares. If preferred dividends are zero or not mentioned, use net income directly. Present the result as a plain floating point number (e.g., 4.5) when the answer format requires it.
[calc-00023] helpful=2 harmful=0 :: For future value or compound interest calculations (e.g., FV = PV × (1 + r)^n), compute the growth factor (1 + r)^n with high precision (at least 6-8 decimal places) before multiplying by the present value. Avoid rounding intermediate results; only round the final answer to the required precision (e.g., nearest hundredth). This prevents small rounding errors from amplifying and ensures accuracy.
[calc-00024] helpful=0 harmful=0 :: Put-Call Parity for European options: C + X*e^(-rt) = P + S, where C is call price, P is put price, X is strike price, S is current stock price, r is risk-free rate as a decimal, and t is time to expiration in years. To solve for the put price: P = C + X*e^(-rt) - S. Convert r to decimal (e.g., 1.5% = 0.015) and t to years (e.g., 6 months = 0.5) before computing the present value of the strike X*e^(-rt). Carry full precision through intermediate steps and round only the final answer to the required precision.
[calc-00025] helpful=0 harmful=0 :: Purchasing Power Parity (PPP): S1/S0 = P1/P0, where S is the exchange rate (domestic currency per foreign currency) and P is the price level. To find the new price level, rearrange to P1 = P0 × (S1/S0). Ensure exchange rate direction is consistent with price levels (e.g., if S is domestic per foreign, then P is foreign price level). Compute with full precision and round only the final answer as instructed.
[calc-00026] helpful=3 harmful=0 :: Gordon Growth Model (constant dividend growth valuation): P0 = D1 / (r - g), where D1 is the next period's expected dividend, r is the required rate of return, and g is the constant growth rate. Ensure D1 is the forward dividend (not the most recent paid dividend) and that r > g. Convert percentages to decimals before computing (e.g., 6% = 0.06, 2% = 0.02), compute the denominator (r - g) first, then divide. Example: D1 = 1.10, r = 0.06, g = 0.02 gives P0 = 1.10 / 0.04 = 27.5. Round only the final result as instructed.
[calc-00027] helpful=0 harmful=0 :: Debt-to-Equity Ratio = Total Liabilities / Shareholder Equity. Substitute the given values directly, perform the division, and present the result as a plain floating point number (e.g., 750,000 / 250,000 = 3.0). Ensure both numerator and denominator are in the same units.
[calc-00028] helpful=2 harmful=0 :: Current Ratio = Current Assets / Current Liabilities. Substitute the given values directly, perform the division, and present the result as a plain floating point number (e.g., 50000 / 25000 = 2.0). Ensure both numerator and denominator are in the same units.
[calc-00029] helpful=0 harmful=0 :: Modigliani-Miller theorem with taxes: Levered Value = Unlevered Value + (Tax Rate × Debt). Convert the tax rate from percentage to decimal (e.g., 18% = 0.18) before multiplying by debt. Compute the tax shield as Tax Rate × Debt, then add to the unlevered value. Round only the final result as instructed.
[calc-00030] helpful=1 harmful=0 :: Operating Margin = Operating Income / Revenue. When the answer format is a plain floating point number and the question asks for a margin or rate, multiply the ratio by 100 to express as a percentage (e.g., 70,000 / 500,000 = 0.14; multiply by 100 to get 14.0). This follows the margin/rate conversion convention (calc-00012, err-00013).
[calc-00031] helpful=0 harmful=0 :: Covered Interest Rate Parity (CIRP): F = S0 × (1 + r_domestic)^t / (1 + r_foreign)^t, where S0 is the spot rate expressed as domestic currency per foreign currency, r_domestic is the domestic interest rate, r_foreign is the foreign interest rate, and t is the time to maturity in years. Convert rates to decimals before computing. If the computed forward rate is slightly below the expected answer (e.g., 1.29 vs 1.30), check whether the problem might intend a 1-year horizon (t=1) or simple interest (F = S0 × (1 + r_domestic×t) / (1 + r_foreign×t)); also verify the spot rate direction—if S0 is foreign per domestic, invert it first. Always carry full precision through intermediate steps and round only the final answer as instructed.
[calc-00032] helpful=2 harmful=0 :: Annuity Due Present Value: PV = C × [1 - (1+r)^(-n)] / r × (1+r). This applies when cash flows occur at the beginning of each period. The relationship is PV_annuity_due = PV_ordinary × (1+r). When a problem states cash flows occur 'annually for the next n years' without specifying timing, compute both ordinary annuity and annuity due PVs, or look for context clues (e.g., 'payments begin immediately', 'at the start of each year'). If the expected answer is larger than the ordinary annuity PV by a factor of (1+r), the problem intends annuity due. Always carry full precision through intermediate steps and round only the final answer.
[calc-00034] helpful=0 harmful=0 :: Beta = Covariance(security returns, market returns) / Variance(market returns). Ensure both values are in consistent units (typically decimals) and do not confuse variance with standard deviation.

Identify any cash outflows for long-term assets as CapEx, then subtract from operating cash flow. Do not confuse operating expenses with capital expenditures.

[calc-00041] helpful=0 harmful=0 :: Weighted Average Cost of Capital (WACC) = (E/V) × r_e + (D/V) × r_d × (1 - T), where E is market value of equity, D is market value of debt, V = E + D, r_e is cost of equity, r_d is cost of debt, and T is the corporate tax rate. Compute weights as E/V and D/V, convert all rates and T to decimals, apply the tax shield to the cost of debt (after-tax cost of debt = r_d × (1 - T)), then sum the weighted components. Keep rates as decimals unless a percentage is explicitly requested; round only the final result as instructed (e.g., to nearest hundredth). Example: E=230,000, D=270,000, V=500,000, r_e=0.055, r_d=0.03, T=0.21 → WACC = 0.46×0.055 + 0.54×0.03×(1-0.21) = 0.038098 ≈ 0.04.
[calc-00043] helpful=0 harmful=0 :: When using put-call parity to solve for time to expiration t, rearrange the formula to isolate the exponential term: e^(-rt) = (P + S - C) / X. Compute the right-hand side; if it is greater than 1, then -rt > 0, which would imply a negative t (since r > 0). A value greater than 1 signals inconsistent data because e^(-rt) must be ≤ 1 for t ≥ 0. In such cases, double-check the problem statement for possible misassigned values (e.g., call and put prices swapped, strike and stock price swapped) or consider that the problem might intend a different formula. Always verify that the computed t is positive and economically meaningful before finalizing the answer.
[calc-00045] helpful=0 harmful=0 :: Sharpe Ratio = (R_p - R_f) / σ_p, where R_p is portfolio return, R_f is risk-free rate, and σ_p is the standard deviation of portfolio returns. Convert all percentages to decimals before computing (e.g., 8% = 0.08, 2% = 0.02, 10% = 0.10). Compute excess return, divide by standard deviation, and round only the final result as instructed. Trailing zeros do not affect numerical correctness (e.g., 0.60 is equivalent to 0.6).
[calc-00046] helpful=0 harmful=0 :: Relative PPP can be used to solve for an unknown initial price level when absolute PPP gives unrealistic results. If S is domestic currency per foreign currency, relative PPP is S1/S0 = (P1_domestic/P0_domestic) / (P1_foreign/P0_foreign). When one price level is unknown and the problem implies that the foreign price level at time 1 equals the domestic price level at time 0 (P1_foreign = P0_domestic), rearrange to P0_foreign = P1_domestic × (S1/S0). Example: P0_MX = 108 × (0.073/0.075) = 105.12. Always check if the computed absolute PPP price level (e.g., 1333.33) is implausible compared to the other country's price level (e.g., 100); if so, the problem likely intends this relative PPP rearrangement with a base-year equivalence assumption.

## COMMON MISTAKES TO AVOID

[err-00004] helpful=3 harmful=2 :: Do not convert a decimal rate to a percentage number (e.g., 0.055 to 5.5) unless the problem explicitly asks for a percentage. Converting changes the scale by 100× and will produce an answer that is numerically wrong for floating-point expectations. Also, apply rounding to the decimal value, not the percentage value: 0.055 rounded to the nearest hundredth is 0.06, not 5.5.
[err-00011] helpful=0 harmful=0 :: When a problem mentions 'future payments' or 'rent payments' over multiple periods, do not automatically assume it requires discounting the entire annuity. Check if the question might be asking for the present value of a single payment (e.g., the first year's payment). If the expected answer is much smaller than the annuity present value, it likely refers to a single cash flow. Re-read the wording carefully: phrases like 'these future rent payments' could be ambiguous; consider whether only one payment is being valued.
[err-00013] helpful=3 harmful=2 :: Do not assume that a 'plain floating point number' always means the decimal form. For margin and rate questions (e.g., Net Profit Margin, Gross Margin, Return on Assets), the ground truth often expects the percentage value (e.g., 5.0 for 5%). If you compute a ratio like 0.05, check whether the question is asking for a margin or rate; if so, multiply by 100 before outputting. This is an exception to the general rule in err-00004: converting to percentage is correct when the quantity is explicitly a margin or rate and the answer format is a plain number.
[err-00018] helpful=1 harmful=0 :: Do not overgeneralize the margin/rate percentage conversion rule (calc-00012, err-00013) to all rates. Dividend yield and similar per-share ratios should remain as decimals when a plain floating point number is requested. Always check whether the specific quantity is conventionally expressed as a percentage in the given context; if not, keep the decimal form.
[err-00033] helpful=1 harmful=1 :: Do not default to end-of-period (ordinary annuity) cash flow timing when a problem is ambiguous about whether payments occur at the beginning or end of each period. The phrase 'annually for the next n years' can imply either. If the ground truth or context suggests beginning-of-period cash flows, use the annuity due formula (PV_ordinary × (1+r)). Consider computing both and checking which aligns with any additional clues (e.g., 'payments start today', 'lease payments due in advance').
[err-00038] helpful=0 harmful=1 :: Do not apply the margin/rate percentage conversion rule (calc-00012, err-00013) to the cost of equity or required rate of return derived from valuation models such as the Gordon Growth Model. When a question asks for the cost of equity as a plain floating point number without explicitly requesting a percentage, keep the decimal result (e.g., 0.07, not 7.0). The example conversion in the question (e.g., '5 million to 5000000.0') refers to unit scaling, not percentage conversion; do not interpret it as a cue to multiply rates by 100.
[err-00040] helpful=0 harmful=0 :: When a question asks for the 'impact' of a change on a rate or value (e.g., 'impact on the cost of equity' after a growth rate increase), do not automatically compute the difference (Δ). In finance contexts, 'impact' often means the resulting new value after the change, not the change itself. Check if the answer choices or expected format match a direct computation of the new rate (e.g., r2 = D1/P0 + g_new). If the computed difference is small (e.g., 0.02) but the expected answer is larger and matches the new rate (e.g., 0.08), interpret 'impact' as the new value. When ambiguous, consider providing the new value as the primary answer, especially if it aligns with a straightforward calculation.
[err-00042] helpful=0 harmful=0 :: When solving for time to expiration (t) using put-call parity (C + X*e^(-rt) = P + S) and the computed t is negative, do not simply output the negative value. A negative time is economically impossible and indicates that the given data are inconsistent with put-call parity. In such cases, re-check the inputs: verify that the call and put prices, strike, and stock price are correctly assigned, and consider whether the problem might have a typo or expect a different formula arrangement (e.g., solving for a different variable). If the ground truth is a large positive number (e.g., 99.1), it likely comes from a different calculation or a misinterpretation; however, as a test-taker, you should still flag the inconsistency and consider alternative interpretations rather than forcing a negative answer.
[err-00044] helpful=0 harmful=0 :: When a present value calculation for a series of equal cash flows yields an answer that is exactly (1+r) times smaller than the expected/ground truth answer, the ground truth is using annuity due (beginning-of-period) timing. Even if the problem explicitly states 'end of each year', some ground truths still assume beginning-of-year cash flows; if your ordinary annuity PV multiplied by (1+r) matches the expected answer, switch to annuity due. As a safeguard, when the computed PV seems plausible but does not match, check whether PV × (1+r) equals the expected value before assuming a calculation error.
[err-00047] helpful=0 harmful=0 :: Do not abandon relative PPP when absolute PPP yields an unrealistic price level (e.g., P0_MX = 100/0.075 = 1333.33 when the other country's price level is 100). If the exchange rate is given as domestic per foreign and the computed foreign price level is orders of magnitude larger than the domestic price level, the problem likely assumes that the foreign price level at time 1 equals the domestic price level at time 0 (P1_foreign = P0_domestic). In that case, use P0_foreign = P1_domestic × (S1/S0) instead of P0_foreign = P0_domestic / S0. Verify by checking if the result is of the same order of magnitude as the known price level.
