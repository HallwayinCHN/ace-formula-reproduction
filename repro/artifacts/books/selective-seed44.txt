## FORMULAS & CALCULATIONS

[calc-00001] helpful=0 harmful=0 :: Enterprise Value (EV) = Market Capitalization + Total Debt - Cash and Cash Equivalents. Use this formula when calculating EV for valuation multiples.
[calc-00002] helpful=0 harmful=0 :: EV/EBITDA multiple = Enterprise Value / EBITDA. Compute EV first, then divide by EBITDA.
[calc-00004] helpful=0 harmful=0 :: Present Value of Ordinary Annuity = C * [(1 - (1+r)^-n) / r], where C is the periodic cash flow, r is the discount rate, and n is the number of periods. Use when cash flows occur at the end of each period.
[calc-00005] helpful=0 harmful=0 :: Present Value of Annuity Due = (Present Value of Ordinary Annuity) * (1 + r), or equivalently, sum the present values with the first cash flow at t=0. Use when cash flows occur at the beginning of each period.
[calc-00007] helpful=0 harmful=0 :: Effective Annual Rate (EAR) = (1 + r/n)^n - 1, where r is the nominal annual rate (as a decimal) and n is the number of compounding periods per year. Use when converting a nominal rate to an effective annual rate.
[calc-00009] helpful=0 harmful=0 :: Return on Equity (ROE) = Net Income / Shareholder's Equity. After computing the ratio, multiply by 100 to express it as a percentage, as ROE is conventionally reported as a percentage (e.g., 0.2 becomes 20.0%).
[calc-00011] helpful=0 harmful=0 :: GDP (Expenditure Approach) = Consumption (C) + Investment (I) + Government Spending (G) + Net Exports (X - M), where X is exports and M is imports. Use this formula when calculating GDP from expenditure components.
[calc-00014] helpful=0 harmful=0 :: Relative Purchasing Power Parity (PPP): (S1 - S0) / S0 ≈ inflation_domestic - inflation_foreign, where S is the exchange rate expressed as domestic currency per unit of foreign currency. Use this to estimate inflation differentials or expected exchange rate changes.
[calc-00015] helpful=0 harmful=0 :: Absolute PPP: P_domestic = S × P_foreign, where S is the exchange rate expressed as domestic currency per unit of foreign currency. Rearrange to solve for the foreign price level: P_foreign = P_domestic / S. Ensure the exchange rate direction matches this definition.
[calc-00019] helpful=0 harmful=0 :: Interest Rate Parity (IRP): F = S × (1 + r_domestic) / (1 + r_foreign), where S is the spot rate expressed as domestic currency per unit of foreign currency, F is the forward rate in the same convention, r_domestic is the domestic interest rate, and r_foreign is the foreign interest rate. Use when computing forward exchange rates from interest rate differentials.
[calc-00022] helpful=0 harmful=0 :: Free Cash Flow (FCF) = Cash Flow from Operations (CFO) - Capital Expenditures (CapEx). Use this formula when asked to compute free cash flow; ensure both components are in the same units and format the final answer as a plain floating point number if required.
[calc-00023] helpful=1 harmful=0 :: When applying GDP = C + I + G + (X - M), treat net exports as a signed value: if imports exceed exports, net exports is negative and must be subtracted. Also, if components are given in billions, convert each to plain numbers by multiplying by 1,000,000,000 before summing, and express the final GDP as a plain number (e.g., 640 billion = 640,000,000,000).
[calc-00025] helpful=0 harmful=0 :: Net Profit Margin = (Net Profit / Revenue) * 100. Use this when a question provides both revenue and net profit and asks for 'Net Profit from selling products' or similar phrasing that could indicate a profitability ratio rather than an absolute amount. Express the result as a percentage (e.g., 150,000 / 2,000,000 * 100 = 7.5).
[calc-00029] helpful=0 harmful=0 :: Sortino Ratio = (R_p - R_f) / σ_d, where R_p is the portfolio return, R_f is the risk-free rate, and σ_d is the downside deviation. Convert all percentage inputs to decimals before computing, then divide the excess return by the downside deviation and round the final answer to two decimal places.
[calc-00030] helpful=0 harmful=0 :: Put-Call Parity: C + X * e^(-r*t) = P + S, where C is call price, P is put price, X is strike price, S is spot price, r is risk-free rate, and t is time to expiration. Rearrange to solve for any variable, e.g., e^(-r*t) = (P + S - C) / X. Use when relating call and put prices for European options.
[calc-00032] helpful=0 harmful=0 :: Dividend Yield = Annual Dividend per Share / Price per Share. Compute as a decimal (e.g., 9 / 150 = 0.06) and output the decimal form when a plain floating point number is requested; only multiply by 100 if a percentage is explicitly required.
[calc-00033] helpful=0 harmful=0 :: Debt-to-Equity Ratio = Total Liabilities / Shareholder's Equity. Use this formula when asked to compute the debt-to-equity ratio; ensure both values are in the same units and express the result as a plain floating point number (e.g., 750,000 / 250,000 = 3.0).
[calc-00035] helpful=0 harmful=0 :: CAPM (Capital Asset Pricing Model): Expected Return = Risk-free rate + Beta × (Expected market return - Risk-free rate). When percentages are given, convert them to decimals before calculation (e.g., 2% = 0.02, 6% = 0.06), compute the market risk premium, multiply by beta, add the risk-free rate, and round the final answer as instructed (e.g., to the nearest hundredth).
[calc-00036] helpful=0 harmful=0 :: Return on Assets (ROA) = Net Income / Total Assets. After computing the ratio, multiply by 100 to express it as a percentage, as ROA is conventionally reported as a percentage (e.g., 0.06 becomes 6.0). When a question asks for a plain floating point number and mentions 'necessary conversions', output the percentage value (e.g., 6.0), not the decimal (0.06).
[calc-00039] helpful=0 harmful=0 :: Weighted Average Cost of Capital (WACC) = (E/V) * Re + (D/V) * Rd * (1 - Tc), where E is market value of equity, D is market value of debt, V = E + D, Re is cost of equity, Rd is cost of debt, and Tc is corporate tax rate. Compute WACC as a decimal. When a plain floating point number is requested, output the decimal rounded as instructed (e.g., 0.04), not the percentage (e.g., 4.0).
[calc-00040] helpful=0 harmful=0 :: Operating Margin = (Operating Income / Revenue) * 100. When a question asks for operating margin as a plain floating point number, output the percentage value (e.g., 90,000 / 750,000 = 0.12, then 0.12 * 100 = 12.0), not the decimal ratio (0.12). This convention applies to profitability margins such as operating margin, gross margin, and net profit margin.
[calc-00042] helpful=0 harmful=0 :: Balance of Trade = Exports - Imports. When values are given in millions, multiply each by 1,000,000 to convert to full numbers before subtracting, and express the final answer as a plain floating point number (e.g., $750M exports - $450M imports = 300,000,000.0).
[calc-00044] helpful=0 harmful=0 :: Gordon Growth Model (Constant Dividend Growth): Cost of Equity (r) = D1 / P0 + g, where D1 is the expected dividend per share next period, P0 is the current stock price, and g is the constant growth rate. Use when computing the cost of equity from dividend and price data. Convert percentages to decimals before calculation and round as instructed.

## COMMON MISTAKES TO AVOID

[err-00003] helpful=0 harmful=0 :: Ensure all monetary values (market cap, debt, cash, EBITDA) are in the same units (e.g., all in millions or all in dollars) before performing calculations to avoid unit mismatch errors.
[err-00006] helpful=0 harmful=0 :: When a problem states cash flows occur 'at the end of each year', verify whether the expected answer might assume an annuity due (beginning of year). If the computed ordinary annuity PV does not match, consider multiplying by (1+r) to adjust to annuity due, as some contexts or ground truths may use that convention despite the wording.
[err-00008] helpful=0 harmful=0 :: When a question asks for a rate as a plain floating point number, provide the decimal form (e.g., 0.02 for 2%), not the percentage form (2.02). Always check whether the answer should be in decimal or percentage format, and follow the ground truth's convention if specified.
[err-00010] helpful=0 harmful=3 :: Financial ratios such as ROE, ROA, ROI, and margins are often expressed as percentages. When a question asks for a plain floating point number and the context is a financial ratio, check if a percentage conversion is expected. Multiply the decimal ratio by 100 to get the percentage value (e.g., 0.2 * 100 = 20.0).
[err-00012] helpful=0 harmful=0 :: When a value is given in millions (e.g., 4,300 million), convert it to plain numbers by multiplying by 1,000,000 (e.g., 4,300,000,000) before performing calculations to avoid unit errors.
[err-00013] helpful=0 harmful=1 :: When computing powers like (1+r)^n, avoid manual step-by-step approximations with intermediate rounding. Use direct exponentiation with high precision (e.g., calculator or software) and round only the final answer to prevent accumulated errors.
[err-00016] helpful=0 harmful=1 :: When an exchange rate is given as 'Currency A to Currency B' (e.g., 'Canadian Dollar to Mexican Peso'), interpret it as 1 unit of Currency A equals S units of Currency B (e.g., 1 CAD = S MXN). Thus, S is MXN per CAD. Do not assume the inverse unless explicitly stated.
[err-00017] helpful=0 harmful=0 :: In PPP problems, if your computed answer using standard absolute or relative PPP does not match the expected format or magnitude, consider alternative problem conventions. For example, some problems may expect P0* = P1 × (S1/S0) or similar rearrangements. Always double-check the exchange rate direction and the timing of price levels (initial vs. final) before finalizing.
[err-00018] helpful=0 harmful=0 :: In Black-Scholes or similar option pricing calculations, use high-precision values for the cumulative normal distribution N(d1) and N(d2) (e.g., from a calculator or software with many decimal places) and carry full precision through all intermediate steps. Round only the final answer to the required number of decimal places. Small differences in N(d) (e.g., 0.463970 vs. 0.463971) can change the final price by a cent, so avoid rounding intermediate values.
[err-00020] helpful=0 harmful=0 :: When an exchange rate is quoted as 'GBP/USD' or similar 'X/Y' format, do not assume it means Y per X. In many finance contexts, 'GBP/USD' means GBP per USD (i.e., 1 USD = X GBP), which is the inverse of the intuitive 'USD per GBP'. If the computed forward rate direction contradicts the interest rate differential (e.g., higher domestic rate should depreciate domestic currency), try the inverse quote interpretation and see if the result aligns with the expected magnitude.
[err-00021] helpful=0 harmful=0 :: When a problem instructs to 'round to the nearest hundredth if necessary' but the ground truth answer has only one decimal place (e.g., 1.3 instead of 1.34), consider that the expected rounding may be to the nearest tenth. If your computed value is close to a one-decimal number (e.g., 1.3044 rounds to 1.3), check whether rounding to one decimal place matches the expected format.
[err-00024] helpful=0 harmful=0 :: In GDP expenditure calculations, do not assume net exports are positive. Compute (Exports - Imports) exactly; a trade deficit yields a negative value that reduces GDP. Additionally, when inputs are in billions, multiply by 1,000,000,000 to convert to plain numbers, and ensure the final answer is in plain number format if required.
[err-00026] helpful=0 harmful=0 :: When a question provides both a numerator and a denominator (e.g., revenue and net profit) and asks for a metric like 'Net Profit from selling products', do not assume the given profit figure is the final answer. Check if the expected answer is a ratio or margin by considering the magnitude: if the given profit is large relative to revenue but the expected answer is a small number (e.g., 7.5), it likely requires computing a percentage (Net Profit / Revenue * 100). Always perform the ratio calculation when both components are present.
[err-00027] helpful=0 harmful=2 :: When a question asks for a financial ratio (e.g., dividend yield, ROE, net profit margin) as a plain floating point number, do not automatically multiply by 100 to convert to a percentage. Compute the ratio as a decimal (e.g., 6/60 = 0.1) and output that decimal unless the question explicitly requests a percentage. Pay close attention to the requested output format to avoid off-by-100 errors.
[err-00028] helpful=0 harmful=0 :: When a problem states cash flows occur 'annually for the next n years' without specifying whether they are at the beginning or end of each year, do not default to an ordinary annuity. Consider both possibilities: compute the ordinary annuity PV and also the annuity due PV (ordinary PV * (1+r)). If the ordinary PV seems too low relative to the context or expected magnitude, the ground truth may assume beginning-of-year cash flows. Always check if the first cash flow could occur immediately (t=0).
[err-00031] helpful=0 harmful=0 :: In option pricing or put-call parity problems, if solving for time to expiration yields a negative value, the inputs are inconsistent (arbitrage opportunity or data error). Do not simply take the absolute value. Instead, re-examine the formula rearrangement, check units (e.g., days vs. years), and consider that the expected answer may involve a different calculation or scaling (e.g., multiplying by strike price). If the ground truth is known to be much larger, look for a factor like the strike price or a unit conversion.
[err-00034] helpful=0 harmful=0 :: When a present value problem states a cash flow 'every year for the next n years' but the computed annuity PV is much larger than the expected answer, consider that the ground truth may correspond to discounting only a single payment (e.g., the first year's cash flow) rather than all n payments. For example, if $8,000 is received 'every year for the next 3 years' at 4%, the ordinary annuity PV is $22,000.71, but a ground truth of $7,692.31 equals 8000/1.04, i.e., the PV of just the first payment. In such cases, reverse-engineer the intended interpretation from the expected magnitude: if the answer is close to C/(1+r), the question likely asks for the PV of a single sum, not an annuity.
[err-00037] helpful=0 harmful=1 :: For return ratios such as ROA, ROE, and ROI, do not output the decimal ratio when a plain floating point number is requested. These ratios are almost always expressed as percentages in finance contexts. If the problem mentions 'conversions' or the expected magnitude is a whole number (e.g., 6.0 rather than 0.06), multiply the decimal by 100. This differs from ratios like dividend yield, where the decimal form may be expected; always check the specific ratio's conventional presentation and any contextual clues.
[err-00038] helpful=0 harmful=0 :: When a question asks for a plain floating point number and provides an example like '5 million should be 5000000.0', do not convert decimals to percentages. For WACC and similar rates, keep the value in its natural decimal form (e.g., 0.038098) and round as instructed (e.g., to 0.04), without multiplying by 100.
[err-00041] helpful=0 harmful=0 :: Distinguish between ratio types when deciding whether to multiply by 100: profitability margins (operating margin, gross margin, net profit margin) and return ratios (ROE, ROA, ROI) are conventionally expressed as percentages, so multiply the decimal by 100 even when a plain floating point number is requested (e.g., 0.12 becomes 12.0). In contrast, ratios like dividend yield and debt-to-equity are often expected in decimal form. When in doubt, consider the conventional presentation of the specific ratio and any contextual clues (e.g., an example showing '5 million = 5000000.0' does not imply decimals should stay as decimals for margins).
[err-00043] helpful=0 harmful=0 :: When a question asks for the 'impact' of a change on a financial metric (e.g., 'impact on the cost of equity' after a growth rate increase), do not automatically compute the difference between the old and new values. In many contexts, 'impact' means the resulting value of the metric after the change. If the computed difference is small (e.g., 0.02) but the expected answer magnitude matches the new value (e.g., 0.08), provide the new value. Consider the phrasing and expected magnitude to decide between delta and new value.
