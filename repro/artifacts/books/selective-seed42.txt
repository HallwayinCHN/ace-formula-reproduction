## STRATEGIES & INSIGHTS

## FORMULAS & CALCULATIONS

[calc-00004] helpful=0 harmful=0 :: For CAPM: Expected Return = risk-free rate + beta × (market return - risk-free rate). Convert all percentages to decimals before calculation, then round the final decimal result as instructed.
[calc-00007] helpful=0 harmful=0 :: For Sortino Ratio: (R_p - R_f) / σ_d, where R_p is portfolio return, R_f is risk-free rate, and σ_d is downside deviation. Convert percentages to decimals before calculation, then round the final result as instructed.
[calc-00008] helpful=1 harmful=1 :: For present value of an ordinary annuity: PV = PMT × [1 - (1 + r)^(-n)] / r, where PMT is the periodic payment, r is the interest rate per period (as a decimal), and n is the number of periods. For annuity due, multiply the result by (1 + r).
[calc-00012] helpful=1 harmful=0 :: For dividend yield: Dividend Yield = annual dividends per share / stock price per share. Express the result as a decimal (e.g., 0.1) when the question asks for a plain floating point number, not as a percentage (10%).
[calc-00014] helpful=1 harmful=0 :: For compound interest (FV = PV × (1 + r)^n) and similar exponential calculations, carry full precision through all intermediate steps—especially when computing (1 + r)^n. Do not round the growth factor before multiplying by the principal. Round only the final answer as instructed. Small rounding errors in the exponentiated term can amplify when multiplied by a large principal, causing the final answer to miss the ground truth.
[calc-00015] helpful=0 harmful=0 :: For P/E ratio: P/E = market price per share / earnings per share. The result is a dimensionless number; express it as a plain floating point number (e.g., 20.0) when requested, without unit conversion or percentage formatting.
[calc-00016] helpful=0 harmful=0 :: For debt-to-equity ratio: Debt-to-Equity = total liabilities / shareholder equity. Express the result as a plain floating point number (e.g., 3.0) when requested, without percentage formatting.
[calc-00019] helpful=0 harmful=0 :: For GDP using the expenditure approach: GDP = C + I + G + (X - M), where C is consumption, I is investment, G is government spending, X is exports, and M is imports. Compute net exports (X - M) first, then sum all components. If components are given in millions, convert the final result to a full number by multiplying by 1,000,000 (e.g., 9100 million = 9,100,000,000.0).
[calc-00021] helpful=0 harmful=0 :: For interest rate parity (forward exchange rate): F = S × (1 + r_d) / (1 + r_f), where S is the spot rate, r_d is the domestic interest rate, and r_f is the foreign interest rate. Use this formula WITHOUT exponentiation even for multi-year periods unless the problem explicitly states to use compound interest. For example, a 2-year forward rate typically uses F = S × (1 + r_d) / (1 + r_f), not F = S × [(1 + r_d)/(1 + r_f)]^2. If simple interest over n years is expected, use F = S × (1 + r_d × n) / (1 + r_f × n).
[calc-00025] helpful=0 harmful=0 :: For free cash flow (FCF): FCF = Cash Flow from Operations - Capital Expenditures. Ensure both values are in the same units (e.g., both in dollars or both in millions) before subtracting. Express the result as a plain floating point number (e.g., 12000.0) when requested, without additional formatting.
[calc-00027] helpful=0 harmful=0 :: For the Gordon Growth Model (constant dividend growth): Cost of Equity = (D1 / P0) + g, where D1 is the expected dividend per share next period, P0 is the current stock price, and g is the growth rate. If the question provides the current dividend (D0), use D1 = D0 × (1 + g). Express the result as a decimal unless percentage format is explicitly requested.
[calc-00034] helpful=0 harmful=0 :: For relative purchasing power parity (PPP): (S1/S0) = (P1/P0) / (P1*/P0*), where S is the exchange rate (domestic per foreign), P is the domestic price level, and P* is the foreign price level. When solving for an initial foreign price level (P0*) and the problem provides P1, S0, S1, and P0, rearrange to P0* = P1* * (S0/S1) * (P1/P0). If the problem implies no foreign inflation (P1* = P0*), this simplifies to P0* = P1 * (S1/S0). Always use both time periods' data; do not apply absolute PPP at a single point in time when relative PPP is intended.
[calc-00037] helpful=0 harmful=0 :: For trade balance: Trade Balance = Exports - Imports. When values are given in billions, convert each to full numbers by multiplying by 1,000,000,000 before subtracting (e.g., $2 billion = 2,000,000,000.0; $1.5 billion = 1,500,000,000.0; trade balance = 500,000,000.0). Express the final result as a plain floating point number.

## COMMON MISTAKES TO AVOID

[err-00001] helpful=0 harmful=1 :: When a question asks for a 'plain floating point number' and provides an example of unit conversion (e.g., 5 million to 5000000.0), express rates as decimals (e.g., 0.055), not as percentages (e.g., 5.5).
[err-00002] helpful=0 harmful=0 :: Always apply rounding instructions to the final decimal value. For example, 0.055 rounded to the nearest hundredth is 0.06, not 5.5.
[err-00005] helpful=0 harmful=0 :: When a question asks for a rate (e.g., unemployment rate, interest rate, growth rate), the standard convention is to express the answer as a percentage, not as a decimal proportion. After computing the rate as a decimal, multiply by 100 to convert to percentage points. For example, a change of 16,000 in a labor force of 400,000 gives 0.04, which should be reported as 4.0 (percentage points), not 0.04.
[err-00009] helpful=0 harmful=0 :: When a problem mentions payments 'every year for the next N years', ensure you treat it as an annuity with N payments, not a single payment. Double-check the number of periods and whether payments occur at the beginning (annuity due) or end (ordinary annuity) of each period.
[err-00011] helpful=1 harmful=0 :: For profit margin (and similar ratios like return on assets/equity expressed as percentages), after computing the ratio as a decimal, multiply by 100 to express it as a percentage number (e.g., 0.05 becomes 5.0). Even if the question asks for a 'plain floating point number', the expected answer is often the percentage value, not the decimal fraction. Check if the ratio is conventionally reported as a percentage and convert accordingly.
[err-00017] helpful=0 harmful=0 :: For operating margin (operating income / revenue), after computing the ratio as a decimal, multiply by 100 to express it as a percentage number (e.g., 0.14 becomes 14.0). Even if the question asks for a 'plain floating point number', the expected answer is often the percentage value, not the decimal fraction. Check if the ratio is conventionally reported as a percentage and convert accordingly.
[err-00024] helpful=0 harmful=0 :: Do not default to an ordinary annuity (end-of-period cash flows) without considering annuity due. If the problem is ambiguous about timing and your ordinary annuity result does not match expectations, compute the annuity due value by multiplying the ordinary annuity PV by (1 + r). In some finance contexts, 'annual cash inflows' may be assumed to occur at the beginning of each year.
[err-00028] helpful=0 harmful=0 :: When solving for time to expiration (t) or any variable that must be positive, a negative result indicates inconsistent inputs or a misapplied formula. Do NOT take the absolute value and report it as the answer. Instead, re-check the formula arrangement, verify that all rates are in decimal form (e.g., 2% = 0.02, not 0.0002), and confirm that call/put prices and strike/spot prices are assigned to the correct variables. If the inconsistency persists, consider whether the problem expects a different formula or interpretation.
[err-00030] helpful=0 harmful=0 :: When a problem states cash flows occur at the 'end of each year' but your computed ordinary annuity PV does not match the expected answer, do not assume your calculation is wrong. Instead, compute the annuity due value by multiplying your ordinary annuity PV by (1 + r). If that matches the expected answer, the ground truth likely assumes beginning-of-year cash flows despite the wording. This discrepancy can occur in problem sets with errors or ambiguous phrasing.
[err-00033] helpful=0 harmful=0 :: Do not return the absolute net profit figure when the question asks for 'Net Profit from selling products' and both revenue and net profit are given. This phrasing typically requests the net profit margin. Always check if a ratio or percentage is being asked for, especially when the expected answer is a small number like 7.5.
[err-00035] helpful=0 harmful=0 :: In multi-period problems (e.g., PPP with data at time 0 and time 1), do not ignore the later data points and apply a single-period formula (like absolute PPP at time 0). Instead, use a relative formula that incorporates all given values (e.g., relative PPP). If your answer seems inconsistent with the provided later data, re-read the problem to ensure you are using the intended multi-period relationship.
## PROBLEM-SOLVING HEURISTICS

## CONTEXT CLUES & INDICATORS

[ctx-00003] helpful=0 harmful=0 :: Phrases like 'plain floating point number' or examples showing conversion from words to numbers (e.g., '5 million to 5000000.0') indicate that the answer should be in decimal form, not percentage points.
[ctx-00006] helpful=0 harmful=0 :: The phrase 'unemployment rate' (or any 'rate') typically signals that the expected answer is in percentage form. Even if the question requests a 'plain floating point number' or provides examples of unit conversion, rates are conventionally reported as percentages (e.g., 4.0 for 4%). Do not stop at the decimal proportion; convert to percentage by multiplying by 100.
[ctx-00010] helpful=0 harmful=0 :: Phrases like 'every year for the next X years', 'annual payments', or 'periodic installments' indicate an annuity problem. Use annuity formulas rather than single-payment present value formulas.
[ctx-00013] helpful=0 harmful=0 :: When a question asks for 'dividend yield' and specifies a plain floating point number, the expected answer is the decimal form (e.g., 0.1), not the percentage form (10%). Trailing zeros (0.10) are acceptable as they are numerically equivalent.
[ctx-00018] helpful=1 harmful=0 :: Financial ratios such as operating margin, profit margin, return on assets, and return on equity are conventionally expressed as percentages. When such a ratio is requested, even with instructions for a 'plain floating point number', the expected answer is likely the percentage value (e.g., 14.0 for 14%), not the decimal (0.14). Multiply by 100 after computing the ratio.
[ctx-00020] helpful=0 harmful=0 :: When a question provides values in 'millions' (or 'billions') and asks for a plain number, remember to multiply the computed total by 1,000,000 (or 1,000,000,000) to convert to the full numeric value. For example, a GDP of 9100 million should be reported as 9,100,000,000.0, not 9100.0.
[ctx-00022] helpful=0 harmful=0 :: When a problem asks for a 'forward rate' or 'forward exchange rate' over a multi-year horizon (e.g., '2-year forward rate'), the standard convention in many finance problems is to apply the interest rate parity formula F = S × (1 + r_d) / (1 + r_f) without exponentiating for the number of years. Do not assume compound interest over n periods unless the problem explicitly mentions compounding or provides annual compounding instructions.
[ctx-00023] helpful=0 harmful=0 :: When a problem states cash flows occur 'annually for the next N years' without specifying beginning or end of period, be aware that some sources (especially certain textbooks or problem sets) may intend beginning-of-year cash flows (annuity due). If your computed ordinary annuity PV seems plausible but the expected answer is higher, check whether multiplying by (1 + r) yields the expected value—this indicates an annuity due interpretation.
[ctx-00026] helpful=0 harmful=0 :: When a question asks for the 'impact' of a change on a rate (e.g., 'impact on the cost of equity if the growth rate increases'), the intended answer is often the new rate value after the change, not the difference. Look for phrasing like 'impact on X' versus 'change in X' or 'increase in X'—the former typically asks for the resulting value, while the latter asks for the delta.
[ctx-00029] helpful=0 harmful=0 :: If a computed time to expiration from put-call parity is negative, this often signals a unit mismatch in the risk-free rate (e.g., using 0.02% instead of 2%, or vice versa) or a swap of call and put prices. Re-examine the inputs: a negative t is impossible, so the correct approach is to revisit the formula and data rather than forcing a positive result. In some cases, the ground truth may reflect a different compounding convention or a simple-interest approximation.
[ctx-00031] helpful=0 harmful=0 :: If a present value or NPV question involves annual cash flows and the expected answer is higher than your ordinary annuity calculation, check whether the difference equals a factor of (1 + r). This is a strong indicator that the ground truth uses annuity due (beginning-of-period) cash flows, even if the problem text says 'end of each year'. Always verify by computing both interpretations when the answer seems off.
[ctx-00032] helpful=0 harmful=0 :: When a question provides both revenue and net profit and asks for 'Net Profit from selling products', it is often asking for the net profit margin (a percentage), not the absolute net profit amount. Compute (Net Profit / Revenue) * 100 and express as a percentage number (e.g., 7.5 for 7.5%).
[ctx-00036] helpful=0 harmful=0 :: When an exchange rate is given (e.g., 0.075), carefully determine the quotation direction (e.g., CAD per MXN vs MXN per CAD) from the problem context or by checking which interpretation yields a plausible answer. In PPP problems, the direction affects whether you multiply or divide by the exchange rate. If the computed price level seems implausibly large or small, try the reciprocal interpretation.
