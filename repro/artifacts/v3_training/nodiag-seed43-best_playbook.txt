## STRATEGIES & INSIGHTS

## FORMULAS & CALCULATIONS

[calc-00001] helpful=3 harmful=0 :: Earnings Per Share (EPS) = (Net Income - Preferred Dividends) / Average Shares Outstanding. Use this formula when asked to compute EPS.
[calc-00003] helpful=1 harmful=0 :: Put-Call Parity: C - P = S - X e^{-rt} for continuous compounding, or C - P = S - X/(1+r)^t for discrete annual compounding. Use when relating call and put prices to the underlying asset and strike price.
[calc-00005] helpful=2 harmful=1 :: Present Value of Annuity Due = PMT * [1 + 1/(1+r) + 1/(1+r)^2 + ... + 1/(1+r)^(n-1)] = PMT * [(1 - (1+r)^(-n))/r] * (1+r). Equivalently, PV_annuity_due = PV_ordinary_annuity * (1+r). Use when cash flows occur at the beginning of each period.
[calc-00009] helpful=0 harmful=0 :: Effective Annual Rate (EAR) = (1 + r/n)^n - 1, where r is the nominal annual rate and n is the number of compounding periods per year. Use when asked to compute the effective annual rate from a nominal rate with multiple compounding periods.
[calc-00011] helpful=1 harmful=0 :: Treynor Ratio = (Portfolio Return - Risk-Free Rate) / Beta. Use when evaluating risk-adjusted performance relative to systematic risk. Convert percentages to decimals before calculation (e.g., 14% = 0.14, 1% = 0.01), then round the final decimal as instructed.
[calc-00012] helpful=1 harmful=0 :: Free Cash Flow (FCF) = Operating Cash Flow - Capital Expenditures. Use when asked to compute free cash flow from operating cash flow and capital expenditures.
[calc-00013] helpful=1 harmful=0 :: Price-to-Earnings (P/E) Ratio = Price per Share / Earnings per Share (EPS). Use when asked to compute the P/E ratio from price and EPS. Ensure both values are in consistent units (e.g., per-share basis) and format the final answer as a plain floating point number rounded as instructed.
[calc-00014] helpful=0 harmful=0 :: Sharpe Ratio = (Portfolio Return - Risk-Free Rate) / Standard Deviation of Portfolio Returns. Use when evaluating risk-adjusted performance relative to total risk. Convert percentages to decimals before calculation (e.g., 8% = 0.08, 2% = 0.02, 10% = 0.10), then round the final decimal as instructed. A result of 0.6 is equivalent to 0.60.
[calc-00015] helpful=0 harmful=0 :: Working Capital = Current Assets - Current Liabilities. Use when asked to compute working capital from balance sheet items. Format the final answer as a plain floating point number as requested.
[calc-00016] helpful=0 harmful=0 :: Days Sales Outstanding (DSO) = (Accounts Receivable / Credit Sales) × Number of Days. Use when asked to compute DSO or average collection period. Ensure AR and Credit Sales cover the same period as the stated number of days.
[calc-00017] helpful=1 harmful=0 :: Market Capitalization = Total Shares Outstanding × Price per Share. Use when asked to compute market cap. Ensure you use the total shares outstanding after any issuance, not add new shares again if the total is already given.
[calc-00019] helpful=0 harmful=0 :: Relative Purchasing Power Parity (PPP): P1/P0 = S1/S0, where P is the price level and S is the spot exchange rate. Rearrange as needed (e.g., P1 = P0 * (S1/S0)). Use when asked to compute a price level or inflation differential given exchange rates, or vice versa. Ensure exchange rates are quoted consistently (e.g., domestic currency per unit of foreign currency) before applying the ratio.
[calc-00021] helpful=0 harmful=0 :: Debt Service Coverage Ratio (DSR) = Net Operating Income / Total Debt Service. Use when asked to compute DSR from NOI and debt service. Ensure both values are in the same units (e.g., annual) and round the final decimal as instructed (e.g., 400,000 / 300,000 = 1.333... rounds to 1.33).
[calc-00022] helpful=0 harmful=0 :: Weighted Average Cost of Capital (WACC) = (E/V) * Re + (D/V) * Rd * (1 - Tc), where E is market value of equity, D is market value of debt, V = E + D, Re is cost of equity, Rd is pre-tax cost of debt, and Tc is corporate tax rate. Use when asked to compute WACC. Ensure equity and debt weights sum to 1 and always use the after-tax cost of debt (Rd * (1 - Tc)).
[calc-00023] helpful=0 harmful=0 :: When applying put-call parity and the compounding convention is not specified, either discrete annual compounding (C - P = S - X/(1+r)^t) or continuous compounding (C - P = S - X e^{-rt}) is acceptable. For small rates and short maturities, both methods typically yield the same rounded answer. Convert time to years (e.g., 6 months = 0.5) and rate to decimal (e.g., 1.5% = 0.015) before computing.
[calc-00025] helpful=4 harmful=0 :: Trade Balance = Exports - Imports. Use when asked to compute a trade balance or net exports from export and import values. Convert billions to full numbers by multiplying by 1,000,000,000 (e.g., $2 billion = 2,000,000,000) before subtracting, and present the result as a plain floating point number.
[calc-00026] helpful=1 harmful=0 :: Current Ratio = Current Assets / Current Liabilities. Use when asked to compute the current ratio from balance sheet items. Format the final answer as a plain floating point number as requested.
[calc-00027] helpful=0 harmful=0 :: Enterprise Value (EV) = Market Capitalization + Total Debt - Cash and Cash Equivalents. EV/EBITDA = EV / EBITDA. Use when asked to compute enterprise value or an EV/EBITDA multiple. Ensure debt and cash are total values (not per-share) and EBITDA is for the same period.
[calc-00028] helpful=0 harmful=0 :: Net Profit Margin = (Net Profit / Revenue) × 100. Use when asked for 'net profit from selling products' or similar phrasing when both revenue and net profit are given and the expected answer is a small number (e.g., 7.5), indicating a percentage rather than the absolute profit amount.
[calc-00031] helpful=2 harmful=0 :: Gordon Growth Model (Dividend Discount Model) for Cost of Equity: Cost of Equity = (D1 / P0) + g, where D1 is next year's expected dividend, P0 is the current stock price, and g is the dividend growth rate. Use when asked to compute cost of equity from dividend, price, and growth rate. Ensure D1 is the next period's dividend (if current dividend D0 is given, D1 = D0 * (1+g)) and g is in decimal form (e.g., 2% = 0.02).
[calc-00035] helpful=1 harmful=0 :: Dividend Yield = Annual Dividends per Share / Price per Share. Use when asked to compute dividend yield from dividend and price data. Convert the result to a decimal (e.g., 6/60 = 0.1) and format as a plain floating point number rounded as instructed.
[calc-00036] helpful=0 harmful=0 :: Relative PPP with two countries: (P1_foreign / P0_foreign) = (P1_domestic / P0_domestic) × (S1 / S0), where S is the exchange rate quoted as foreign currency per unit of domestic currency. Rearrange to solve for the unknown price level ratio. Use this when comparing inflation between two countries and exchange rate changes. Ensure the exchange rate quote direction matches the formula; if S is domestic per foreign, invert the ratio (S0/S1) instead.
[calc-00039] helpful=2 harmful=0 :: Operating Margin = (Operating Income / Revenue) × 100. Use when asked to compute operating margin. The result should be expressed as a percentage (e.g., 14.0 for 14%), not as a decimal (0.14). Multiply the ratio by 100 to convert to percentage form.
[calc-00041] helpful=0 harmful=0 :: Sortino Ratio = (Portfolio Return - Risk-Free Rate) / Downside Deviation. Use when evaluating risk-adjusted performance relative to downside risk only. Convert percentages to decimals before calculation (e.g., 6% = 0.06, 1.5% = 0.015, 3.5% = 0.035), then round the final decimal as instructed (e.g., 0.045 / 0.035 = 1.2857... rounds to 1.29).
[calc-00042] helpful=0 harmful=0 :: Dividend Payout Ratio = Dividends per Share / Earnings per Share (EPS). Use when asked to compute the proportion of earnings paid out as dividends. Ensure both dividends and EPS are on a per-share basis. The result is typically expressed as a decimal (e.g., $0.50 / $2.50 = 0.20, which is equivalent to 0.2).
[calc-00045] helpful=0 harmful=0 :: Jensen's Alpha = R_i - [R_f + β_i * (R_m - R_f)], where R_i is the actual portfolio return, R_f is the risk-free rate, β_i is the portfolio beta, and R_m is the market return. Use when asked to compute Jensen's Alpha or excess return over CAPM-predicted return. Convert all percentages to decimals before calculation (e.g., 8% = 0.08, 2% = 0.02, 5% = 0.05), compute the expected return as R_f + β_i*(R_m - R_f), then subtract from R_i. Round the final decimal as instructed (e.g., 0.039 rounds to 0.04).
[calc-00046] helpful=0 harmful=0 :: When computing market capitalization, convert shares outstanding from millions (or billions) to full units before multiplying by price per share (e.g., 5 million shares = 5,000,000). Present the final result as a plain floating point number (e.g., 275000000.0) if the question requests that format.
[calc-00049] helpful=1 harmful=0 :: Gordon Growth Model (Dividend Discount Model) for Stock Price: P0 = D1 / (r - g), where P0 is the current stock price, D1 is next year's expected dividend, r is the required rate of return (cost of equity), and g is the constant dividend growth rate. Use when asked to compute the current price of a stock given the next dividend, required return, and growth rate. Convert percentages to decimals (e.g., 6% = 0.06, 2% = 0.02) and ensure the numerator is the next period's dividend (D1), not the current dividend (D0). Round the final answer as instructed (e.g., 1.10 / (0.06 - 0.02) = 27.50).
[calc-00050] helpful=0 harmful=0 :: Debt-to-Equity Ratio = Total Liabilities / Shareholder Equity. Use when asked to compute the debt-to-equity ratio from balance sheet items. Ensure both values are total amounts (not per-share) and format the final answer as a plain floating point number rounded as instructed (e.g., 750,000 / 250,000 = 3.0).
[calc-00051] helpful=0 harmful=0 :: Modigliani-Miller with Corporate Taxes: Levered Value = Unlevered Value + (Tax Rate × Debt). The second term is the present value of the interest tax shield. Use when asked to compute the value of a levered firm given its unlevered value, debt level, and corporate tax rate. Convert the tax rate to decimal (e.g., 18% = 0.18) before multiplying by debt, then add to the unlevered value (e.g., 2,200,000 + 0.18 × 400,000 = 2,272,000).
[calc-00052] helpful=0 harmful=0 :: Return on Assets (ROA) = Net Income / Total Assets. ROA is conventionally expressed as a percentage. After computing the decimal ratio (e.g., 78,000 / 1,300,000 = 0.06), multiply by 100 to convert to percentage form (0.06 × 100 = 6.0) and output that value. Use when asked to compute ROA or similar return ratios (e.g., ROE, ROI) unless the question explicitly requests a decimal.
[calc-00054] helpful=0 harmful=0 :: Return on Equity (ROE) = Net Income / Shareholder's Equity. ROE is conventionally expressed as a percentage. After computing the decimal ratio (e.g., 2,000,000 / 10,000,000 = 0.20), multiply by 100 to convert to percentage form (0.20 × 100 = 20.0) and output that value when the question asks for a plain floating point number. Use when asked to compute ROE; do not leave the answer as a raw decimal (0.2) unless the question explicitly requests a decimal.
[calc-00055] helpful=0 harmful=0 :: Beta = Covariance(asset, market) / Variance(market). Use when asked to compute beta from covariance and market variance. Beta measures systematic risk; substitute the given covariance and variance directly (e.g., 0.007 / 0.025 = 0.28).
[calc-00056] helpful=0 harmful=0 :: Interest Coverage Ratio = EBIT / Interest Expense. Use when asked to compute the interest coverage ratio from earnings before interest and taxes (EBIT) and interest expense. Ensure both values are in the same units and format the final answer as a plain floating point number rounded as instructed (e.g., 2,000,000 / 400,000 = 5.0).
[calc-00057] helpful=1 harmful=0 :: GDP (Expenditure Approach) = C + I + G + (X - M), where C is consumption, I is investment, G is government spending, X is exports, and M is imports. Compute net exports as X - M (subtract imports from exports). Use when asked to compute GDP from expenditure components. Convert billions to full units by multiplying by 1,000,000,000 before summing, and present the result as a plain floating point number (e.g., 320 + 150 + 180 + (100 - 110) = 640 billion = 640,000,000,000.0).
[calc-00059] helpful=1 harmful=0 :: Capital Asset Pricing Model (CAPM): Expected Return = Risk-Free Rate + Beta × (Market Return - Risk-Free Rate), i.e., E(R) = Rf + β(E(Rm) - Rf). Use when asked to compute expected return, cost of equity, or required return from risk-free rate, beta, and market return. Convert all percentages to decimals before calculation (e.g., 1% = 0.01, 4% = 0.04), compute the market risk premium as (E(Rm) - Rf), multiply by beta, add the risk-free rate, and round only at the final step as instructed (e.g., 0.01 + 1.5 × (0.04 - 0.01) = 0.055, which rounds to 0.06).
[calc-00061] helpful=0 harmful=0 :: For Black-Scholes option pricing, use high-precision values for N(d1) and N(d2) (at least 6 decimal places) and carry full precision through intermediate multiplications. Round only the final call or put price to the required number of decimal places. This avoids cumulative rounding errors that can shift the final answer by 0.01 or more.
[calc-00062] helpful=0 harmful=0 :: Future Value (FV) = PV * (1 + r)^n. When computing compound interest or future value, calculate the growth factor (1 + r)^n with full precision (e.g., using a calculator or software to at least 7-8 significant digits) and avoid rounding intermediate results. Multiply by the principal only after obtaining the high-precision growth factor, then round the final answer to the required decimal places. Premature rounding of (1 + r)^n can cause discrepancies of 0.01 or more in the final result.
[calc-00063] helpful=0 harmful=0 :: Gross Profit Margin = ((Revenue - COGS) / Revenue) × 100. Use when asked to compute gross profit margin or gross margin. First compute gross profit as Revenue minus COGS, then divide by Revenue and multiply by 100 to express as a percentage. Round to the required precision (e.g., two decimal places) and output as a plain floating point number without the percent sign if specified.
[calc-00064] helpful=0 harmful=0 :: Alternative annuity due computation: PV_annuity_due = PMT + PMT × [(1 - (1+r)^(-(n-1)))/r]. That is, add the immediate first payment to the present value of an ordinary annuity of n-1 remaining payments. Use this as a cross-check against the standard formula PV = PMT × [(1 - (1+r)^(-n))/r] × (1+r); both should yield the same result.
## CODE SNIPPETS & TEMPLATES

## COMMON MISTAKES TO AVOID

[err-00002] helpful=0 harmful=0 :: Do not treat trailing zeros as errors: numerical equivalence (e.g., 3.50 vs 3.5) is acceptable unless the question explicitly requires a specific decimal format.
[err-00004] helpful=0 harmful=0 :: When solving for time to expiration (t) in put-call parity, a negative result may indicate an arbitrage opportunity or a mispricing. Double-check the sign and consider whether the problem expects an absolute value or a different compounding convention.
[err-00006] helpful=2 harmful=1 :: When a problem states 'end of each year' but the expected answer is higher than the ordinary annuity PV by a factor of (1+r), the intended calculation is likely an annuity due (beginning-of-year cash flows). Verify by computing both PV_ordinary and PV_due; if the expected answer matches PV_due, adjust your assumption despite the wording.
[err-00008] helpful=2 harmful=0 :: When a question asks for a plain floating point number rounded to the nearest hundredth, apply rounding directly to the computed decimal value (e.g., 0.0056 rounds to 0.01). Do not convert to percentage points first unless explicitly instructed; doing so can cause an off-by-factor-of-100 error.
[err-00010] helpful=0 harmful=0 :: For EAR problems, carefully follow the requested output format: if the question asks for a plain floating point number, provide the decimal value (e.g., 0.02), not the percentage (2.02%). Convert to percentage only when explicitly instructed.
[err-00018] helpful=0 harmful=0 :: When a problem states total shares outstanding after an issuance (e.g., '4 million shares outstanding, including the additional 500,000 shares'), do not add the new shares again. Use the given total directly to avoid double-counting.
[err-00024] helpful=0 harmful=0 :: Do not assume continuous compounding is required for option pricing problems unless explicitly stated. If the problem does not specify, discrete compounding is acceptable and often yields the same rounded result for small rates; avoid unnecessary conversion to continuous rates that could introduce rounding differences.
[err-00029] helpful=0 harmful=0 :: Do not simply restate a value that is already explicitly given in the problem. If the question asks for a quantity that appears to be provided directly (e.g., 'net profit' when net profit is given), re-evaluate: it likely asks for a derived ratio or percentage (e.g., net profit margin = net profit / revenue × 100). Check whether the expected answer magnitude is plausible for the given data.
[err-00033] helpful=0 harmful=0 :: Do not assume that phrases like 'every year for the next N years' always require an annuity calculation. If the expected answer is much smaller than the annuity PV and equals a single payment discounted one period, the problem may intend only the first payment's present value. When the ground truth conflicts with a mathematically correct annuity result, consider whether a single cash flow interpretation aligns with the expected magnitude.
[err-00034] helpful=0 harmful=0 :: When a computed value is close to a rounding boundary (e.g., 1.28903), consider that the ground truth may round to fewer decimal places (e.g., one decimal place to get 1.3) even if the instruction says 'round to the nearest hundredth'. If the instruction's rounding yields an answer that seems slightly off from a simpler rounded value, check whether rounding to one decimal place matches the expected format; the instruction may be a distractor or the ground truth may use a coarser convention.
[err-00038] helpful=0 harmful=0 :: Do not use absolute PPP (P = S × P*) to solve for an initial price level when the problem provides price level changes and exchange rate changes over time. Absolute PPP may not hold, and the question likely requires relative PPP to find the inflation differential. Use relative PPP to relate the ratios of price levels to the exchange rate ratio.
[err-00040] helpful=1 harmful=0 :: Do not assume all financial ratios should be expressed as decimals. Margin ratios (e.g., operating margin, net profit margin, gross margin) are typically expressed as percentages. When a question asks for a margin, multiply the ratio by 100 unless explicitly instructed to provide a decimal. This contrasts with ratios like Sharpe ratio or Treynor ratio, which are usually left as decimals.
[err-00043] helpful=0 harmful=0 :: When a question asks for the 'impact' of a change on a financial metric (e.g., 'impact on the cost of equity' after a growth rate increase), do not automatically compute the difference (new minus old). In many finance contexts, 'impact' is used loosely to mean the resulting value after the change. Check whether the expected answer magnitude matches the new value rather than the delta; if the delta is small (e.g., 0.02) but the new value is a typical cost of equity (e.g., 0.08), the question likely expects the new value. When ambiguous, consider providing the new value as the primary answer.
[err-00047] helpful=0 harmful=0 :: When a question asks for the effect on a rate (e.g., unemployment rate, interest rate) as a floating point number, it typically expects the change in percentage points, not the decimal proportion. After computing the decimal change (e.g., 16,000 / 400,000 = 0.04), multiply by 100 to convert to percentage points (0.04 * 100 = 4.0) and output that value. This contrasts with err-00008: the distinction is whether the requested quantity is a rate change (use percentage points) versus a general ratio or return (use decimal).
[err-00053] helpful=0 harmful=1 :: Do not leave return ratios such as ROA (Net Income / Total Assets) as raw decimals when the ground truth expects a percentage. If the computed decimal is small (e.g., 0.06) and the question asks for a return ratio, the expected answer is likely the percentage value (6.0). Multiply by 100 before outputting. This is an exception to the general rule for plain floating point numbers: return ratios are conventionally reported as percentages, similar to margin ratios.
[err-00060] helpful=0 harmful=0 :: When a problem does not explicitly state whether cash flows occur at the beginning or end of each period, do not default solely to the ordinary annuity (end-of-period) assumption. Consider both ordinary annuity and annuity due interpretations, especially in contexts like lease payments or investments with immediate returns where beginning-of-period cash flows may be implied. If the expected answer matches PV_ordinary × (1+r), the intended convention is annuity due.
## PROBLEM-SOLVING HEURISTICS

## CONTEXT CLUES & INDICATORS

[ctx-00007] helpful=1 harmful=0 :: If the expected answer for an annuity problem equals the ordinary annuity PV multiplied by (1+r), it indicates the problem expects an annuity due calculation. This pattern can help identify timing convention mismatches between problem text and ground truth.
[ctx-00020] helpful=0 harmful=0 :: For relative PPP problems, always verify the direction of the exchange rate quote. If the rate is quoted as domestic currency per unit of foreign currency, the price level ratio equals the exchange rate ratio directly (P1/P0 = S1/S0). If quoted inversely, invert the ratio to avoid a reciprocal error.
[ctx-00030] helpful=0 harmful=0 :: If the expected answer is a small number (e.g., 7.5) while the given absolute values are large (e.g., revenue $2,000,000, profit $150,000), the question likely asks for a percentage or ratio (e.g., margin) rather than an absolute amount. Use the ratio of the given values to confirm.
[ctx-00032] helpful=0 harmful=0 :: If the expected answer for a multi-period cash flow problem equals a single payment discounted one period (e.g., PMT/(1+r)), the ground truth may be treating the problem as a single future payment rather than an annuity. Check whether the expected answer matches PMT/(1+r)^1 before committing to an annuity calculation.
[ctx-00044] helpful=0 harmful=0 :: If a question asks for the 'impact' of a change and the computed difference is very small relative to typical values for that metric (e.g., a 2% change in cost of equity when cost of equity is around 6-8%), the expected answer may be the new metric value rather than the change. Finance problems often use 'impact' to mean the updated value; verify by checking if the new value aligns with common ranges or the problem's context.
[ctx-00048] helpful=0 harmful=0 :: If a question asks for the 'effect on the unemployment rate' or similar rate change and provides absolute changes in the numerator and denominator (e.g., change in unemployed persons and labor force), the expected answer is likely the percentage point change (decimal change × 100). Check whether the ground truth magnitude is around 100 times the computed decimal; if so, output the percentage point value.
[ctx-00058] helpful=0 harmful=0 :: If exports and imports are equal in a trade balance problem, the balance of trade is zero. Output 0.0 as a plain floating point number when the question requests that format; do not omit the decimal or treat zero as a missing value.
## OTHERS
[misc-00037] helpful=0 harmful=0 :: In relative PPP problems, if the computed inflation factor (e.g., 1.0512) when applied to a base price level of 100 yields a value that matches the expected answer (e.g., 105.12), but the question asks for the initial price level, consider that the question may have intended to ask for the final price level or that the initial level is normalized to 100. Always verify which price level is being requested and whether a base year normalization is implied.
