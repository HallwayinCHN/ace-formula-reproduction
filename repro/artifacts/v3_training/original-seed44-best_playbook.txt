## STRATEGIES & INSIGHTS

[sai-00002] helpful=0 harmful=0 :: When a problem provides an unlevered firm value, a debt amount, and a tax rate, and asks for the levered value (assuming perpetual debt and risk-free tax shield), use the APV method: add Tax Rate × Debt to the unlevered value.
[sai-00007] helpful=1 harmful=0 :: When asked for a P/E ratio and given a share price and EPS, directly divide price by EPS; ensure both figures are on the same per-share basis and in consistent units before dividing.
[sai-00013] helpful=1 harmful=0 :: When computing the present value of a series of cash flows and the result differs from an expected or ground truth answer by a factor of (1+r), consider that the cash flows may be assumed to occur at the beginning of each period (annuity due) rather than at the end. Adjust by multiplying the ordinary annuity PV by (1+r).
[sai-00019] helpful=1 harmful=1 :: Always match the requested output format for rates: if the question asks for a plain floating point number or decimal rate, output the decimal form (e.g., 0.02), not the percentage (e.g., 2.02). Only multiply by 100 when the question explicitly asks for a percentage.
[sai-00021] helpful=0 harmful=0 :: When a financial ratio such as ROE, ROA, or profit margin is requested, remember these are conventionally expressed as percentages. Even if the question asks for a plain floating point number, the expected value is typically the percentage figure (e.g., 20.0 rather than 0.2). Multiply the decimal ratio by 100 to convert to percentage points before outputting.
[sai-00029] helpful=1 harmful=0 :: When computing GDP or any aggregate that sums multiple stated figures (e.g., C, I, G, X, M), apply the same unit conversion to every component before adding or subtracting. Mixing converted and unconverted values is a common source of factor-of-1,000,000 errors; verify all inputs share the same unit basis first.
[sai-00039] helpful=0 harmful=0 :: When a computed forward exchange rate is close to but not exactly matching an expected answer (e.g., 1.35 vs. 1.3), consider that the ground truth may use a different rounding convention (e.g., one decimal place) or an alternative formula interpretation. Re-evaluate the exchange rate quotation direction and the placement of interest rates in the CIRP formula before finalizing.
[sai-00043] helpful=1 harmful=0 :: When computing Jensen's Alpha, first convert all percentage inputs (actual return, risk-free rate, market return) to decimals, compute the CAPM expected return as R_f + β_i × (R_m - R_f), then subtract this from the actual return. Round the final decimal alpha to the requested precision (e.g., 0.039 → 0.04).
[sai-00047] helpful=0 harmful=0 :: When using put-call parity, ensure the time to expiration is converted to years (e.g., 6 months = 0.5 years) and compute the present value of the exercise price as X × e^(-rt) with sufficient precision before solving for the unknown option price.
[sai-00048] helpful=0 harmful=0 :: When a question provides both revenue and net profit and asks for a metric like 'Net Profit from selling products', consider whether it is asking for a ratio (e.g., net profit margin) rather than the absolute net profit. If the absolute value is already given, the question likely expects a percentage calculated as (Net Profit / Revenue) × 100. Output the percentage value as a plain floating point number (e.g., 7.5, not 0.075).
[sai-00050] helpful=0 harmful=0 :: When a question asks for a 'plain floating point number' and the metric is a yield (e.g., dividend yield), output the decimal form (e.g., 0.10) rather than the percentage (10.0). Unlike profitability ratios such as ROE or profit margin, yields are often expected as raw decimals in these problems; do not multiply by 100 unless the question explicitly asks for a percentage.
[sai-00053] helpful=0 harmful=0 :: When a present value of annuity problem does not explicitly state whether cash flows occur at the beginning or end of each period, compute both the ordinary annuity PV and the annuity due PV (ordinary PV × (1+r)). If the expected answer is not known, present both or note the assumption; if comparing to a known answer, a difference of exactly (1+r) strongly indicates annuity due.
[sai-00057] helpful=0 harmful=0 :: When put-call parity yields a negative or impossible time to expiration due to inconsistent inputs, take the absolute value of the algebraic solution and check for unit/scaling conventions in the problem. The benchmark may expect the absolute value scaled by a factor (e.g., multiplying by the stock price or exercise price) to match its units.
[sai-00062] helpful=1 harmful=0 :: When a problem states that dividends grow at a constant rate and asks for the current stock price, use the Gordon Growth Model P0 = D1 / (r - g). Verify that the numerator is the next period's dividend (D1) and that both r and g are in decimal form; the denominator must be positive (r > g) for the model to be valid.
[sai-00065] helpful=0 harmful=0 :: When asked for the debt-to-equity ratio, directly divide total liabilities by shareholder equity. Ensure both values are in the same units and output the result as a plain number (e.g., 3.0), not as a percentage or fraction.
[sai-00067] helpful=0 harmful=0 :: When a problem's wording implies multiple annual cash flows (e.g., '$8,000 every year for the next 3 years') but the expected answer is far smaller than the multi-period annuity PV, test whether the expected value equals discounting a single payment by one period: PV = C / (1+r)^1. If it matches, the problem likely intends the PV of the first payment only (or treats the recurring wording as extraneous); do not force a full annuity calculation when the benchmark clearly reflects a single discounting period.
[sai-00071] helpful=0 harmful=0 :: When a question asks for a profitability ratio (ROE, ROA, profit margin) as a plain floating point number without specifying percentage, default to the percentage form (e.g., 6.0 for ROA) rather than the decimal (0.06). This convention overrides general rate formatting rules unless the question explicitly requests a decimal or provides context indicating decimal form.
[sai-00075] helpful=0 harmful=0 :: When computing WACC, always use the after-tax cost of debt (Rd × (1 - T)) rather than the pre-tax rate, base weights on market values of equity and debt (not book values unless specified), verify that equity and debt weights sum to 1, and round only the final WACC result to the requested precision.
[sai-00082] helpful=0 harmful=0 :: When a question asks for the 'impact' of a change in an input (e.g., growth rate) on a rate (e.g., cost of equity), carefully consider whether it asks for the difference (new rate minus old rate) or the new rate value itself. In finance problems, 'impact on the cost of equity' often means the resulting cost of equity after the change, especially when the change is in an input like growth rate. If the answer choices or context are ambiguous, compute both and check which aligns with typical conventions: the new rate is often the expected answer when the question emphasizes the resulting rate rather than the change.
## FORMULAS & CALCULATIONS

[calc-00001] helpful=0 harmful=0 :: Adjusted Present Value (APV) for a levered firm with perpetual debt: Levered Value = Unlevered Value + (Tax Rate × Debt). The second term is the interest tax shield.
[calc-00004] helpful=2 harmful=0 :: Sortino Ratio formula: (R_p - R_f) / σ_d, where R_p is portfolio return, R_f is risk-free rate, and σ_d is downside deviation. It measures risk-adjusted return using only downside risk.
[calc-00006] helpful=1 harmful=0 :: Price-to-Earnings (P/E) ratio formula: P/E = Price per Share / Earnings per Share (EPS). Divide the current share price by the EPS to get the multiple.
[calc-00008] helpful=0 harmful=0 :: Interest Coverage Ratio formula: EBIT / Interest Expense. Use earnings before interest and taxes (EBIT) divided by interest expense to assess a firm's ability to cover interest payments.
[calc-00010] helpful=0 harmful=0 :: Enterprise Value (EV) formula: EV = Market Capitalization + Total Debt - Cash and Cash Equivalents. Use this to compute EV before calculating EV-based multiples.
[calc-00011] helpful=0 harmful=0 :: EV/EBITDA multiple formula: EV/EBITDA = Enterprise Value / EBITDA. Compute EV as Market Cap + Debt - Cash, then divide by EBITDA.
[calc-00012] helpful=2 harmful=0 :: Present Value of an Annuity Due: PV = C × [1 - (1+r)^(-n)] / r × (1+r), where C is the periodic cash flow, r is the discount rate, and n is the number of periods. This assumes cash flows occur at the beginning of each period.
[calc-00015] helpful=0 harmful=0 :: Dividend Payout Ratio formula: Dividends per Share / Earnings per Share (EPS). Express as a decimal (e.g., 0.50 / 2.50 = 0.20).
[calc-00016] helpful=3 harmful=0 :: Balance of Trade formula: Balance of Trade = Exports - Imports. If the values are given in millions, multiply each by 1,000,000 to convert to units before subtracting.
[calc-00018] helpful=0 harmful=0 :: Effective Annual Rate (EAR) formula: EAR = (1 + r/n)^n - 1, where r is the nominal annual rate (in decimal form) and n is the number of compounding periods per year. The result is a decimal rate (e.g., 0.020184 for 2% nominal compounded monthly).
[calc-00022] helpful=0 harmful=0 :: Return on Equity (ROE) formula: ROE = (Net Income / Shareholder's Equity) × 100. Compute the ratio as a decimal, then multiply by 100 to express as a percentage (e.g., 2,000,000 / 10,000,000 = 0.2, then × 100 = 20.0).
[calc-00024] helpful=2 harmful=0 :: Current Ratio formula: Current Ratio = Current Assets / Current Liabilities. Divide current assets by current liabilities to assess short-term liquidity.
[calc-00025] helpful=0 harmful=0 :: Market Capitalization formula: Market Cap = Total Shares Outstanding × Price per Share. Ensure shares outstanding are converted to whole numbers (e.g., 4 million = 4,000,000) before multiplying by the share price.
[calc-00027] helpful=0 harmful=0 :: Days Sales Outstanding (DSO) formula: DSO = (Accounts Receivable / Credit Sales) × Number of Days. Use credit sales (not total sales) in the denominator, and multiply by the number of days in the period (e.g., 30 for a month, 365 for a year). Example: AR = 45,000, Credit Sales = 300,000, Days = 30 → DSO = (45,000 / 300,000) × 30 = 4.5 days.
[calc-00028] helpful=1 harmful=0 :: GDP via Expenditure Approach: GDP = C + I + G + (X - M), where C = consumption, I = investment, G = government spending, X = exports, M = imports. Compute net exports (X - M) first, then sum all components. If inputs are in millions, convert each to base units (× 1,000,000) before summing so the final GDP is in base units.
[calc-00031] helpful=0 harmful=0 :: Relative Purchasing Power Parity (PPP) formula: (S₁/S₀) = (P₁*/P₀*) / (P₁/P₀), where S is the exchange rate (price of foreign currency in domestic currency), P* is the foreign price level, and P is the domestic price level. Use this when given exchange rates and price levels for two time periods to infer inflation differentials or price level changes.
[calc-00032] helpful=0 harmful=0 :: To find a foreign price level using relative PPP: P₁* = P₀* × (S₁/S₀) × (P₁/P₀). If the initial foreign price level P₀* is not given, assume it is 100 (a common normalization in textbook problems) unless otherwise specified.
[calc-00037] helpful=0 harmful=0 :: Covered Interest Rate Parity (CIRP) formula: F = S0 × (1 + r_quote)^t / (1 + r_base)^t, where S0 is the spot exchange rate quoted as units of quote currency per 1 unit of base currency, r_quote is the interest rate of the quote currency, r_base is the interest rate of the base currency, and t is the time in years. For a GBP/USD quote (USD per GBP), GBP is the base currency and USD is the quote currency.
[calc-00040] helpful=1 harmful=0 :: Free Cash Flow (FCF) formula: FCF = Cash Flow from Operations - Capital Expenditures. Identify capital expenditures from context (e.g., spending on equipment, apparatus, or design) and subtract from operating cash flow to get FCF.
[calc-00042] helpful=1 harmful=0 :: Jensen's Alpha formula: Alpha = R_i - [R_f + β_i × (R_m - R_f)], where R_i is the actual portfolio return, R_f is the risk-free rate, β_i is the portfolio beta, and R_m is the market return. The bracketed term is the CAPM expected return. Convert all percentages to decimals before computing, then round the final alpha as instructed.
[calc-00044] helpful=1 harmful=0 :: Net Profit Margin formula: Net Profit Margin = (Net Profit / Revenue) × 100. Compute the ratio as a decimal, then multiply by 100 to express as a percentage (e.g., 25,000 / 500,000 = 0.05, then × 100 = 5.0). When the answer is expected as a plain floating point number representing the percentage, output the percentage value (e.g., 5.0) rather than the decimal ratio (0.05).
[calc-00045] helpful=0 harmful=0 :: Working Capital formula: Working Capital = Current Assets - Current Liabilities. Subtract current liabilities from current assets to assess short-term liquidity. When the question asks for a plain floating point number, output the result directly (e.g., 85,000 - 40,000 = 45000.0).
[calc-00046] helpful=1 harmful=0 :: Put-Call Parity formula: C + Xe^(-rt) = P + S, where C is the call price, P is the put price, X is the exercise price, r is the risk-free rate (decimal), t is time to expiration in years, and S is the current stock price. Rearrange to solve for the unknown (e.g., P = C + Xe^(-rt) - S).
[calc-00051] helpful=0 harmful=0 :: Dividend Yield formula: Dividend Yield = Annual Dividends per Share / Price per Share. Compute the ratio as a decimal (e.g., 6 / 60 = 0.10). When the question asks for a plain floating point number, output the decimal (0.1), not the percentage (10.0).
[calc-00055] helpful=0 harmful=0 :: Alternative method for Present Value of an Annuity Due: PV = C + C × [1 - (1+r)^(-(n-1))] / r. Treat the first payment (at t=0) as undiscounted, then add the present value of the remaining (n-1) payments as an ordinary annuity. This should equal the standard annuity due formula C × [1 - (1+r)^(-n)] / r × (1+r) and serves as a useful cross-check.
[calc-00060] helpful=1 harmful=0 :: Earnings Per Share (EPS) formula: EPS = (Net Income - Preferred Dividends) / Average Shares Outstanding. Subtract preferred dividends from net income first, then divide by the average number of shares outstanding. Example: (500,000 - 50,000) / 100,000 = 4.5.
[calc-00061] helpful=1 harmful=0 :: Gordon Growth Model (Constant Dividend Growth) formula: P0 = D1 / (r - g), where P0 is the current stock price, D1 is the expected dividend in the next period, r is the required rate of return (decimal), and g is the constant dividend growth rate (decimal). Ensure D1 is the next period's dividend, not the most recent dividend D0; if D0 is given, compute D1 = D0 × (1 + g).
[calc-00063] helpful=1 harmful=0 :: Gordon Growth Model rearranged to solve for the cost of equity (required rate of return): r = D1 / P0 + g, where D1 is the expected dividend next period, P0 is the current stock price, and g is the constant dividend growth rate. Ensure g is in decimal form (e.g., 2% = 0.02) and round the final rate as requested.
[calc-00064] helpful=0 harmful=0 :: Debt-to-Equity Ratio formula: Debt-to-Equity = Total Liabilities / Shareholder Equity. Divide total liabilities by shareholder equity to get the ratio. Express the result as a plain floating point number (e.g., 750,000 / 250,000 = 3.0).
[calc-00069] helpful=0 harmful=0 :: Beta formula: Beta = Covariance(asset returns, market returns) / Variance(market returns). Use this to measure an asset's sensitivity to market movements. Ensure covariance and variance are computed consistently (e.g., both using the same return frequency and sample).
[calc-00072] helpful=0 harmful=0 :: Return on Assets (ROA) formula: ROA = (Net Income / Total Assets) × 100. Compute the ratio as a decimal, then multiply by 100 to express as a percentage (e.g., 78,000 / 1,300,000 = 0.06, then × 100 = 6.0). When the answer is expected as a plain floating point number representing the percentage, output the percentage value (e.g., 6.0) rather than the decimal ratio (0.06).
[calc-00073] helpful=0 harmful=0 :: Capital Asset Pricing Model (CAPM) formula: Expected Return = R_f + β × (R_m - R_f), where R_f is the risk-free rate, β is the asset's beta, and R_m is the market return. Convert all percentage inputs to decimals before computing (e.g., 1% = 0.01, 4% = 0.04), then round the final decimal result as instructed.
[calc-00074] helpful=0 harmful=0 :: Weighted Average Cost of Capital (WACC) formula: WACC = (E/V) × Re + (D/V) × Rd × (1 - T), where E is market value of equity, D is market value of debt, V = E + D, Re is cost of equity, Rd is pre-tax cost of debt, and T is the corporate tax rate. Use after-tax cost of debt (Rd × (1 - T)) and ensure weights sum to 1.
[calc-00076] helpful=0 harmful=0 :: Operating Margin formula: Operating Margin = (Operating Income / Revenue) × 100. Compute the ratio as a decimal, then multiply by 100 to express as a percentage (e.g., 90,000 / 750,000 = 0.12, then × 100 = 12.0). When the question asks for a plain floating point number, output the percentage value (e.g., 12.0) rather than the decimal ratio (0.12), because operating margin is conventionally expressed as a percentage.
[calc-00078] helpful=0 harmful=0 :: Sharpe Ratio formula: Sharpe Ratio = (R_p - R_f) / σ_p, where R_p is the portfolio return, R_f is the risk-free rate, and σ_p is the standard deviation of portfolio returns. Convert all percentage inputs to decimals before computing (e.g., 8% = 0.08, 2% = 0.02, 10% = 0.10), then divide the excess return by the standard deviation. Example: (0.08 - 0.02) / 0.10 = 0.6.
[calc-00079] helpful=0 harmful=0 :: Change in Unemployment Rate formula: Change in Unemployment Rate (in percentage points) = (Change in Number of Unemployed / Labor Force) × 100. Use the labor force as the base (not the prior unemployment count), and express the result in percentage points (e.g., 16,000 / 400,000 × 100 = 4.0).
[calc-00080] helpful=0 harmful=0 :: Debt Service Ratio (DSR) formula: DSR = Net Operating Income / Total Debt Service. Divide net operating income by total debt service (annual principal + interest payments) to assess a firm's ability to cover debt obligations. Example: 400,000 / 300,000 = 1.3333..., rounded to 1.33.
[calc-00081] helpful=0 harmful=0 :: Gross Profit Margin formula: Gross Profit Margin = ((Revenue - COGS) / Revenue) × 100, where COGS is cost of goods sold. First compute Gross Profit = Revenue - COGS, then divide by Revenue and multiply by 100 to express as a percentage. Round the final percentage to the requested precision (e.g., nearest hundredth). Example: Revenue = 2,300,000, COGS = 1,700,000 → Gross Profit = 600,000; Margin = (600,000 / 2,300,000) × 100 ≈ 26.09.
[calc-00083] helpful=0 harmful=0 :: Treynor Ratio formula: Treynor Ratio = (R_p - R_f) / β_p, where R_p is the portfolio return, R_f is the risk-free rate, and β_p is the portfolio beta. Convert all percentage inputs to decimals before computing (e.g., 14% = 0.14, 1% = 0.01), compute excess return, divide by beta, and round the final result to the requested precision (e.g., (0.14 - 0.01) / 1.5 = 0.086666... → 0.09).

## COMMON MISTAKES TO AVOID

[err-00003] helpful=0 harmful=0 :: Do not forget to add the tax shield (Tax Rate × Debt) to the unlevered value when computing levered value under APV. Also, ensure the tax rate is in decimal form (e.g., 18% = 0.18).
[err-00005] helpful=0 harmful=0 :: When computing ratios like the Sortino Ratio, convert all percentage inputs (returns, risk-free rate, downside deviation) to decimal form before calculating (e.g., 11% = 0.11, 3% = 0.03, 5% = 0.05).
[err-00009] helpful=0 harmful=0 :: Do not treat numerically equivalent answers as incorrect (e.g., 5.00 vs 5.0). When a question asks for a plain number rounded to the nearest hundredth if necessary, trailing zeros are acceptable and equivalent.
[err-00014] helpful=2 harmful=0 :: Do not rigidly adhere to the phrase 'at the end of each year' if the computed ordinary annuity value is off from the expected answer by exactly (1+r). The problem may intend annuity due treatment despite the wording; check for this pattern and adjust accordingly.
[err-00017] helpful=0 harmful=0 :: When trade or financial figures are stated in millions (or billions), do not subtract the raw stated numbers directly. Convert each figure to base units first (e.g., millions × 1,000,000) so the final answer is expressed in the requested unit.
[err-00020] helpful=0 harmful=2 :: Do not convert a computed decimal rate to a percentage unless the question explicitly requests a percentage. For example, an EAR of 0.020184 rounded to the nearest hundredth is 0.02, not 2.02; outputting 2.02 is a unit/format error.
[err-00023] helpful=0 harmful=1 :: Do not stop at the decimal form when computing profitability ratios like ROE, ROA, or profit margin. These are conventionally reported as percentages, so multiply by 100 to get the percentage value (e.g., output 20.0, not 0.2) even if the question asks for a plain floating point number.
[err-00026] helpful=0 harmful=0 :: When computing market capitalization, do not multiply a share count stated in millions directly by the share price without converting to whole shares. Convert millions to base units first (e.g., 4 million shares = 4,000,000) to avoid a result that is off by a factor of 1,000,000.
[err-00030] helpful=4 harmful=1 :: Do not round or truncate intermediate values (especially exponentiation results like (1+r)^n) too early. Maintain at least 6-8 significant digits during intermediate calculations and only round the final answer to avoid precision errors that affect the rounded result.
[err-00033] helpful=0 harmful=0 :: Do not use absolute PPP (S = P/P*) when the problem provides data for two time periods and asks about changes. Absolute PPP is only appropriate for a single point in time; relative PPP must be used to relate exchange rate changes to inflation differentials.
[err-00034] helpful=0 harmful=0 :: Always verify the exchange rate quotation direction. If S is given as CAD per MXN (e.g., 0.075), then an increase in S means the MXN appreciates. Using the rate in the wrong direction in the PPP formula will invert the result. Check that the units cancel correctly: (S₁/S₀) should be dimensionless.
[err-00035] helpful=0 harmful=0 :: When a problem asks for an initial price level but the computed answer matches the final price level (assuming an initial of 100), re-read the question carefully. It may contain a labeling error or intend to ask for the final price level. In such cases, provide the value that aligns with the standard normalization (initial = 100) and the relative PPP calculation.
[err-00036] helpful=0 harmful=0 :: Do not assume that a calculated value within the reasoning trace is sufficient as the final answer. Always explicitly output the final numerical answer in the required format (e.g., as a plain floating point number) at the end of your response, even if the reasoning is correct. Failure to do so may result in 'No final answer found' errors.
[err-00038] helpful=0 harmful=0 :: In covered interest rate parity, do not assume the domestic rate is always in the numerator or denominator. Identify the base and quote currencies from the exchange rate quotation (e.g., GBP/USD = USD per GBP means GBP is base, USD is quote). The forward rate formula is F = S0 × (1 + r_quote)^t / (1 + r_base)^t. Using the inverse ratio will produce a different result and may not match the expected answer.
[err-00041] helpful=0 harmful=0 :: When computing Free Cash Flow, do not overlook capital expenditures that are described indirectly (e.g., 'spending on printing and design apparatus'). Any investment in long-term assets should be treated as capex and subtracted from operating cash flow.
[err-00049] helpful=0 harmful=0 :: Do not assume that a question asking for 'Net Profit from selling products' is simply asking you to extract the given net profit figure. If both revenue and net profit are provided, the question may intend for you to compute the net profit margin as a percentage. Always check whether the answer requires calculation using both numbers, and be alert to the possibility of a percentage answer.
[err-00052] helpful=0 harmful=0 :: Do not automatically multiply a computed yield (e.g., dividend yield) by 100 to convert to a percentage when the question asks for a plain floating point number. The decimal form (e.g., 0.10) is already a valid floating point number and is often the expected answer; only convert to percentage if explicitly requested.
[err-00054] helpful=0 harmful=0 :: Do not dismiss the annuity due possibility simply because the problem does not explicitly say 'beginning of year.' If your ordinary annuity PV is off from the expected answer by a factor of (1+r), the problem likely intends annuity due. Re-evaluate the timing assumption before finalizing.
[err-00056] helpful=0 harmful=0 :: When computing the Sortino Ratio, after dividing excess return by downside deviation, round the final result to the precision requested (e.g., nearest hundredth). Do not leave the answer as a long unrounded decimal (e.g., 1.285714... should be reported as 1.29 when two decimal places are required).
[err-00058] helpful=0 harmful=0 :: Do not stop without providing a final answer when a calculation yields an impossible or negative result (e.g., negative time in put-call parity). Always commit to an answer by taking the absolute value and applying any implied scaling, even if the result seems inconsistent, to avoid 'No final answer found' errors.
[err-00059] helpful=0 harmful=0 :: Do not ignore large discrepancies between your computed value and the expected answer format. If your result is off by a factor of roughly the stock price or exercise price, consider that the benchmark may use a different scaling convention (e.g., expressing time in units of price) and adjust accordingly.
[err-00066] helpful=0 harmful=0 :: When a question asks for a plain floating point number and the result is a large integer (e.g., 500,000,000), output it without commas or scientific notation (e.g., 500000000.0). Do not format as '500,000,000' or '5e8'; the expected answer is a plain numeric string with a decimal point.
[err-00068] helpful=0 harmful=0 :: Do not assume that a phrase like 'every year for the next N years' always requires computing an N-period annuity. If your annuity PV is much larger than the expected answer (e.g., ~3x), check whether the expected value corresponds to discounting only the first cash flow by one period (C/(1+r)). A large downward discrepancy—unlike the (1+r) factor that signals annuity due—often indicates the problem intends a single payment or a different cash flow count.
[err-00070] helpful=0 harmful=0 :: Do not get stuck deliberating between a computed value and its rounded form when the question explicitly instructs rounding (e.g., 'round to the nearest hundredth if necessary'). Apply the rounding directly: 0.052 rounded to the nearest hundredth is 0.05, so output 0.05 immediately. Overthinking whether to keep 0.052 or round to 0.05, or whether to express as decimal vs. percentage, can prevent you from producing any final answer at all. Commit to the rounded value as instructed.
[err-00077] helpful=0 harmful=0 :: Do not output the decimal ratio (e.g., 0.12) when asked for operating margin as a plain floating point number. Operating margin is conventionally expressed as a percentage, so multiply the decimal ratio by 100 and output the percentage figure (e.g., 12.0 for 12%). This overrides the general rule for rates (err-00020) because margins are profitability ratios, not interest or discount rates.
