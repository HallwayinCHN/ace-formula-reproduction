## FORMULAS & CALCULATIONS

[calc-00001] helpful=0 harmful=0 :: To find the levered value of a company using the Adjusted Present Value (APV) method: Levered Value = Unlevered Value + Tax Shield, where Tax Shield = Debt × Tax Rate. This assumes perpetual debt and a risk-free tax shield.
[calc-00003] helpful=1 harmful=0 :: Sortino Ratio = (R_p - R_f) / σ_d, where R_p is portfolio return, R_f is the minimum acceptable return (or risk-free rate), and σ_d is downside deviation. Always convert percentages to decimals before calculating, and ensure consistent units throughout.
[calc-00004] helpful=1 harmful=0 :: P/E Ratio = Price per Share / Earnings per Share (EPS). Ensure both values are in the same currency and per-share basis; perform division accurately without rounding unless required.
[calc-00005] helpful=0 harmful=0 :: Interest Coverage Ratio = EBIT / Interest Expense. Use consistent units (both in same currency) and express the result as a plain number (e.g., 5.0) unless a ratio format is specified.
[calc-00006] helpful=0 harmful=0 :: Enterprise Value (EV) = Market Cap + Total Debt - Cash and Cash Equivalents. EV/EBITDA = EV / EBITDA. Ensure all monetary values are in the same units before dividing.
[calc-00007] helpful=1 harmful=0 :: Present Value of Annuity Due = (Present Value of Ordinary Annuity) × (1 + r). When a problem states cash flows occur 'at the end of each year' but the expected answer is exactly (1 + r) times the ordinary annuity PV, the cash flows are likely intended as beginning-of-year (annuity due). As a diagnostic, compute both PV_ordinary and PV_due = PV_ordinary × (1 + r); if the expected answer matches PV_due, use annuity due. Alternatively, discount each cash flow at times 0, 1, ..., n-1.
[calc-00008] helpful=0 harmful=0 :: Dividend Payout Ratio = Dividends per Share / Earnings per Share (EPS). Ensure both values are on a per-share basis and in the same currency. Express the result as a decimal (e.g., 0.20) unless a percentage is requested.
[calc-00009] helpful=1 harmful=1 :: When a numerical answer is requested as a plain floating point number, trailing zeros after the decimal do not affect correctness (e.g., 0.20 is equivalent to 0.2). Do not round unnecessarily; provide the exact computed value or round only if specified.
[calc-00010] helpful=3 harmful=0 :: Balance of Trade = Exports - Imports. When exports and imports are given in millions (or any unit), convert both to the same base unit (e.g., multiply by 1,000,000) before subtracting. If exports equal imports, the balance is zero. Output the result as a plain number (e.g., 0.0) unless otherwise specified.
[calc-00011] helpful=4 harmful=0 :: When a question asks for a plain floating point number (e.g., for an interest rate or return), provide the decimal representation, not the percentage. For example, an EAR of 2.018% should be output as 0.02 (rounded to the nearest hundredth), not 2.02. Always double-check the required format and avoid multiplying by 100 unless a percentage is explicitly requested.
[calc-00012] helpful=0 harmful=0 :: Return on Equity (ROE) = Net Income / Shareholder's Equity. After computing the ratio, convert to a percentage by multiplying by 100 (e.g., 0.2 becomes 20.0) when the context or convention expects a percentage value. Financial ratios like ROE are typically expressed as percentages in final answers.
[calc-00014] helpful=0 harmful=0 :: Current Ratio = Current Assets / Current Liabilities. Substitute the given values, perform the division, and express the result as a plain floating point number (e.g., 2.0) unless a different format is specified.
[calc-00015] helpful=1 harmful=0 :: Market Capitalization = Total Shares Outstanding × Price per Share. When a problem mentions an additional share issuance or release, ensure the total shares outstanding reflects the post-issuance count before multiplying by the current price per share.
[calc-00016] helpful=0 harmful=0 :: Days Sales Outstanding (DSO) = (Accounts Receivable / Credit Sales) × Number of Days. Use credit sales (not total sales) if specified; ensure the number of days matches the period (e.g., 30 for monthly, 365 for annual). Output as a plain floating point number.
[calc-00017] helpful=0 harmful=0 :: GDP (Expenditure Approach) = Consumption + Investment + Government Spending + (Exports - Imports). When components are given in millions (or other units), convert all to the same base unit (e.g., multiply by 1,000,000) before summing. Compute net exports as Exports - Imports, then add to the other components. Output the result as a plain number in base units unless otherwise specified.
[calc-00018] helpful=0 harmful=0 :: When computing compound interest or future value (FV = PV × (1 + r)^n), avoid rounding intermediate results. Use direct exponentiation with a calculator or carry at least 6-8 decimal places throughout the calculation, and round only the final answer as instructed. Premature rounding of the exponent or exponential value can cause errors in the final result.
[calc-00019] helpful=0 harmful=0 :: Black-Scholes call option price: C = S * N(d1) - K * e^(-r*t) * N(d2), where d1 = [ln(S/K) + (r + σ^2/2)*t] / (σ*sqrt(t)) and d2 = d1 - σ*sqrt(t). Ensure t is in years, r and σ are decimals, and use accurate standard normal CDF values. Double-check intermediate steps to avoid rounding errors.
[calc-00020] helpful=0 harmful=0 :: When a computed value is very close to a rounding boundary (e.g., 1.289026 rounds to 1.29 but the expected answer is 1.30), consider that the expected answer may use a different rounding convention or precision. If the instruction says 'round to the nearest hundredth' but the ground truth appears to be rounded to one decimal place (e.g., 1.3), output the answer with fewer decimal places (e.g., 1.3 or 1.30) to align with the expected precision. Always double-check if the final answer should be expressed with fewer decimal places than initially computed.
[calc-00021] helpful=1 harmful=0 :: Free Cash Flow (FCF) = Cash Flow from Operations (CFO) - Capital Expenditures (CapEx). Identify CFO and CapEx from the problem, ensure both are in the same units, subtract CapEx from CFO, and output the result as a plain floating point number (e.g., 12000.0) unless otherwise specified.
[calc-00022] helpful=2 harmful=0 :: Jensen's Alpha = R_i - [R_f + β_i × (R_m - R_f)]. Convert all percentages to decimals first, compute the CAPM expected return, subtract it from the actual portfolio return, and round only at the final step. Output as a decimal unless a percentage is explicitly requested.
[calc-00023] helpful=0 harmful=0 :: Net Profit Margin = (Net Profit / Revenue) × 100. After dividing net profit by revenue, multiply by 100 to express the result as a percentage (e.g., 0.05 becomes 5.0). Output the percentage value as a plain floating point number unless otherwise specified.
[calc-00024] helpful=0 harmful=0 :: Working Capital = Current Assets - Current Liabilities. Substitute the given values, subtract liabilities from assets, and output the result as a plain floating point number (e.g., 45000.0) unless otherwise specified.
[calc-00025] helpful=0 harmful=0 :: Put-Call Parity: C + Xe^(-rt) = P + S, where C is call price, P is put price, X is strike price, r is risk-free rate (decimal), t is time to expiration in years, and S is current stock price. To solve for the put price: P = C + Xe^(-rt) - S. Compute the present value of the strike as Xe^(-rt) accurately, ensuring t is in years and r is in decimal form.
[calc-00027] helpful=2 harmful=0 :: Dividend Yield = Annual Dividends per Share / Price per Share. Ensure both values are on a per-share basis and in the same currency. Express the result as a decimal (e.g., 0.1) unless a percentage is explicitly requested.
[calc-00030] helpful=0 harmful=0 :: Put-Call Parity solving for time to expiration: From C + Xe^{-rt} = P + S, rearrange to e^{-rt} = (P + S - C)/X. For a valid positive t, the right-hand side must be between 0 and 1 (since e^{-rt} ≤ 1 for t ≥ 0). If (P + S - C)/X > 1, no positive t exists; the prices violate put-call parity. If valid, t = -ln((P + S - C)/X) / r. Always verify that the computed t is positive and reasonable.
[calc-00031] helpful=1 harmful=0 :: Earnings Per Share (EPS) = (Net Income - Preferred Dividends) / Average Shares Outstanding. Always subtract preferred dividends from net income before dividing, as EPS pertains to common shareholders. Use average shares outstanding if given; otherwise use shares outstanding. Output as a plain floating point number (e.g., 4.5) unless otherwise specified.
[calc-00032] helpful=0 harmful=0 :: When computing Jensen's Alpha or any CAPM-based excess return, do not round intermediate values (e.g., market risk premium, CAPM expected return). Carry full precision through the calculation and round only the final alpha to the specified precision (e.g., nearest hundredth). This prevents rounding errors from propagating into the final answer.
[calc-00033] helpful=2 harmful=0 :: Gordon Growth Model (Constant Dividend Growth): P0 = D1 / (r - g), where D1 is the expected dividend next period, r is the required rate of return (decimal), and g is the constant growth rate (decimal). Convert percentages to decimals before calculating. Output the result as a plain floating point number (e.g., 27.5) unless otherwise specified.
[calc-00034] helpful=1 harmful=0 :: Gordon Growth Model solving for cost of equity (required rate of return): r = (D1 / P0) + g, where D1 is the expected dividend next period, P0 is the current price, and g is the constant growth rate. Convert percentages to decimals before calculating. Output the result as a plain floating point number (e.g., 0.07) unless a percentage is explicitly requested.
[calc-00035] helpful=0 harmful=0 :: Debt-to-Equity Ratio = Total Liabilities / Shareholder Equity. Ensure both values are in the same currency and units. Express the result as a plain floating point number (e.g., 3.0) unless a different format is specified.
[calc-00037] helpful=0 harmful=0 :: Single-period present value: PV = CF / (1 + r)^t. When a problem mentions a payment 'one year from now' or the expected answer matches CF/(1+r), use this simple discounting rather than an annuity formula. As a diagnostic when annuity wording is ambiguous, compute PV_single = CF/(1+r) for the first payment and compare to the expected answer; if it matches, the problem likely intended a single cash flow.
[calc-00038] helpful=0 harmful=0 :: Beta = Covariance(asset, market) / Variance(market). This measures systematic risk. Ensure covariance and variance are computed over the same period and in consistent units. Output as a plain floating point number rounded as instructed (e.g., 0.28).
[calc-00039] helpful=0 harmful=0 :: CAPM expected return: E(R) = R_f + β × (R_m - R_f). Convert all percentages (R_f, R_m) to decimals first, compute the market risk premium as (R_m - R_f), multiply by beta, then add the risk-free rate. Round only the final result to the requested precision (e.g., nearest hundredth). Output as a decimal unless a percentage is explicitly requested.
[calc-00040] helpful=0 harmful=0 :: Relative Purchasing Power Parity (PPP): S1/S0 = P1/P0, where S is the exchange rate (domestic currency per foreign currency) and P is the price level. Rearrange to solve for the unknown: P1 = P0 × (S1/S0) or S1 = S0 × (P1/P0). Substitute given values, carry full precision through the division, and round only the final answer (e.g., to two decimals). Output as a plain floating point number unless otherwise specified.

[calc-00043] helpful=0 harmful=0 :: When rounding to a specified number of decimal places and the digit immediately after the target place is exactly 5 followed by zeros (e.g., 0.055 to the nearest hundredth), apply standard round-half-up: increase the target digit by 1 (0.055 → 0.06). This is the common convention in finance problems unless banker's rounding is explicitly requested.

## COMMON MISTAKES TO AVOID

[err-00013] helpful=0 harmful=2 :: Avoid leaving financial ratios (e.g., ROE, ROA, profit margin) in decimal form when the expected answer is a percentage. Always check if the question or convention requires percentage expression and multiply by 100 accordingly.
[err-00026] helpful=0 harmful=0 :: When a question asks for a profit metric like 'Net Profit from selling products' and provides both revenue and net profit, do not simply return the absolute net profit amount. Instead, check if the question expects a ratio or percentage (e.g., net profit margin = Net Profit / Revenue × 100). If the context or phrasing is ambiguous, compute the margin and output it as a percentage, as this is a common business metric.
[err-00028] helpful=1 harmful=0 :: When a problem states cash flows occur 'annually for the next N years' without specifying timing, do not default to an ordinary annuity (end-of-year). Consider both ordinary annuity and annuity due, and look for clues such as 'starting immediately' or 'beginning of each year'. If the computed ordinary annuity PV does not match expected answer patterns, check if multiplying by (1+r) yields a match, indicating annuity due.
[err-00029] helpful=0 harmful=0 :: When solving exponential equations (e.g., e^{-rt} = k), always check the sign and feasibility of the solution. If k > 1, then -rt = ln(k) > 0, so t must be negative (assuming r > 0). A negative time is impossible, indicating inconsistent input data. Perform a sanity check: for put-call parity, Xe^{-rt} must be ≤ X for t ≥ 0, so if P + S - C > X, no positive time solution exists. Report the inconsistency rather than forcing a positive answer.
[err-00036] helpful=0 harmful=0 :: When a problem's wording suggests multiple cash flows (e.g., 'every year for the next N years') but the expected answer equals a single cash flow discounted one period (e.g., 8000/1.04 = 7692.31), consider that the question may be misstated or intended a single payment. Before finalizing an annuity calculation, compute the single-period PV of one payment as a diagnostic; if it matches the expected answer pattern, override the literal wording and use the single-payment interpretation.
[err-00042] helpful=1 harmful=0 :: When a question asks for a financial ratio (e.g., ROA, ROE, profit margin) as a plain floating point number and does not explicitly state whether to use decimal or percentage form, default to the percentage value for return and profitability ratios (multiply by 100). For example, ROA = 0.06 should be output as 6.0, not 0.06. However, for ratios like dividend yield or payout ratio, decimal form is more common; use context clues or the ratio's typical convention.
[err-00045] helpful=2 harmful=0 :: When computing operating margin (Operating Income / Revenue) or similar profitability ratios (e.g., gross margin, net margin), and the question asks for a plain floating point number, default to expressing the result as a percentage (multiply by 100). For example, an operating margin of 0.12 should be output as 12.0, not 0.12. This aligns with the common convention that profitability ratios are reported in percentage points.
[err-00050] helpful=0 harmful=0 :: When a question asks for the 'impact' of a change on a financial metric (e.g., cost of equity, WACC), do not automatically compute the difference between the old and new values. In finance, 'impact' often refers to the new resulting value after the change. If the question provides a scenario with a changed input and asks for the impact, compute the metric using the new input and output that value. Only compute the difference if the question explicitly asks for 'change' or 'difference'. When ambiguous, consider the context: if the answer choices or expected format suggest a single value rather than a delta, default to the new metric value.
