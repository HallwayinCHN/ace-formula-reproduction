[calc-00023] helpful=0 harmful=0 :: Jensen's Alpha = R_i - [R_f + β_i (R_m - R_f)], where R_i is actual portfolio return, R_f is risk-free rate, β_i is portfolio beta, and R_m is market return. [calc-00028] helpful=0 harmful=0 :: Put-call parity for European options: C + X e^{-rt} = P + S, where C is call price, P is put price, X is strike price, r is risk-free rate (decimal), t is time to expiration in years, and S is current stock price. ## COMMON MISTAKES TO AVOID

[err-00003] helpful=0 harmful=0 :: Do not forget to convert units such as millions to full numbers before subtracting or adding; failing to do so leads to incorrect scale.
[err-00005] helpful=0 harmful=2 :: Do not convert a decimal result to a percentage (e.g., 0.055 to 5.5) when the question asks for a plain floating point number. Express percentages as decimals in the final answer.
[err-00008] helpful=0 harmful=1 :: Do not assume that a 'plain floating point number' always means a decimal. For rate-based questions (e.g., unemployment rate change), the standard convention is to report the percentage value (e.g., 4.0, not 0.04). Over-applying the rule to avoid percentage conversion can cause a factor-of-100 error.
[err-00015] helpful=0 harmful=0 :: Do not automatically assume an annuity when a question mentions multiple future payments. Check if the expected answer matches the present value of a single payment, especially if the calculated annuity value seems too high relative to the given options or context.
[err-00017] helpful=0 harmful=0 :: Do not output a margin or profitability ratio as a decimal (e.g., 0.05) when the conventional expected format is a percentage (e.g., 5.0). Financial margins are typically expressed as percentages; multiply the ratio by 100 before final output unless the question explicitly demands a decimal fraction.
[err-00020] helpful=0 harmful=0 :: For rate-based questions (e.g., Effective Annual Rate, interest rate, growth rate), when the question asks for a 'plain floating point number', the expected format is typically the decimal representation (e.g., 0.02 for 2%), not the percentage value (2.02). Do not multiply by 100 unless the question explicitly asks for a percentage. This is distinct from margin/profitability ratios, which conventionally expect percentage form.
[err-00022] helpful=0 harmful=0 :: Do not treat trailing zeros in decimal answers as errors. For example, 0.10 and 0.1 are numerically equal; both are acceptable unless the question explicitly specifies decimal places. Focus on numerical equivalence rather than formatting differences.
[err-00030] helpful=0 harmful=0 :: Do not convert a computed alpha (or similar return-based metric) from decimal to percentage when the question requests a plain floating point number rounded to a decimal place. For example, if alpha = 0.0056 and rounding to nearest hundredth is required, output 0.01, not 0.56.
