# 第三阶段计划：冻结手册后的五组独立测试

前提：第二阶段六次学习全部完成，六份最佳验证手册的 SHA-256 已写入 `frozen_books.json`。
第二阶段验证集用于选手册，不作为独立效果结论。第三阶段不再学习或选择手册。

## 1. 冻结输入与方法

- 继续使用已冻结的 100 个测试 ID、相同模型、原始预处理和数值判分。
- 三个训练顺序种子为 42、43、44；不声称它们控制服务端模型随机性。
- 五组：空手册、原始 ACE、选择性反思、原始手册＋检索、选择性手册＋检索。
- 检索固定为本地 TF-IDF、最多 12 条、1,500 个本地 tokenizer tokens，不根据测试表现调整。
- 在任何测试调用前冻结评估代码、配置、数据哈希及手册哈希；完成后才统一打开成绩汇总。

## 2. 执行测试

- 每组、每个种子各完成 100 条 pass@1，合计 1,500 次逻辑答题调用。
- 只运行 Generator；测试答案只在输出后供判分器使用，不进入检索、反思或经验更新。
- 每个条件内部串行，条件之间采用相同并行上限。记录本地检索耗时与 API 耗时。
- 使用已有费用预留、共享项目停止线和请求回放机制；不重复收取已完成逻辑请求的调用费用。
- 空输出、无法解析或普通评估异常保留在固定分母中。认证或预算等致命错误停止并保留进度。
- 非空截断沿用上游处理，单列截断率，不能悄悄排除。疑似标签错误保留原主评分。

## 3. 统计与判断

- 汇总每组准确率的三次均值、标准差和方差。
- 预先指定组合方案与原始 ACE 为主要比较；单项改进作为消融，避免看过测试后挑最好的一组。
- 在相同题目、相同训练顺序种子之间作配对比较；按测试题 ID 聚类 bootstrap，保留同题三个种子。
  固定重采样种子 2026、10,000 次，区间条件于这三份训练结果，不把 300 次答题当成 300 道独立题。
- 对主要准确率差异报告 95% 区间，同时说明 100 道题不足以轻易证明 2 个百分点的非劣效。
- 学习成本、答题成本分别报告；同时报告含缓存的记账估算和统一 cache miss 单价下的标准化成本。
- 效率目标仍为相对原始 ACE：观测准确率下降不超过 2 个百分点，且学习或答题成本至少下降 20%。
- 不把“未显著下降”当成“证明不劣”；不预设任一改进一定有效。

## 4. 输出与预算

- 逐题结果、失败及截断统计、调用/token/费用统计、准确率－成本对照图、主要错误案例。
- 将学习费用与 100 次答题费用合并展示完整使用成本，避免只报告部分费用。
- 开始前基于第二阶段实际手册和用量复算剩余费用；项目停止线维持 180 元。
- 若预算不足，停止并报告缺口，不在看过测试效果后缩小样本或改变配置。
- 完成后进入第四阶段：整理不超过 10 页报告、GitHub 运行说明及不超过 15 分钟展示的材料。
