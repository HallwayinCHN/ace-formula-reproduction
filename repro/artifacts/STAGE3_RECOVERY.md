# 第三阶段：用户授权的定时检测与断点恢复

用户在 2026-11-03 要求设置定时检测和断点续跑。此时 220/1500 条预测已保存，三个队列因
明确 HTTP 503 停止；账本保留 12 次失败请求的费用预留。测试成绩尚未开封。

## 保留原始实验契约

- 原始 `stage3_lock.json` 及其 24 个冻结文件不改动，包括模型参数、提示词、样本、六份手册、
  方法实现和判分。没有换模型、重选样本或重新训练。
- 新增独立运行适配器 `resume_holdout.py`，仍调用原来的 `holdout.run_job`。恢复适配器和策略另存
  `stage3_recovery_contract.json`，记录 220 条旧预测及响应回放文件的哈希。
- 明确记录一项运行层变更：此前拒绝恢复的 **明确 HTTP 503** 槽位，现在按用户新授权允许重发相同
  指纹的请求。它不等于确认旧请求未计费；原费用预留完整保留，不把状态改成免费或费用已对账。
- 超时、仍在途、缺失响应、非 503 结果不明请求、鉴权和余额问题不自动恢复。提示词指纹不一致立即停止。

## 检测、试跑和续跑

1. 每次先只读检查 `/user/balance` 和 `/models`。这两个接口可用不代表推理已经正常。
2. 检查通过后，只运行下一道未完成的真实测试题作为试跑，不发送额外的模型探测题。
3. 试跑成功后，恢复原定三个种子队列，队列顺序、并发上限 3 和每条件 100 题均不变。
4. 每次 503 只发起一次尝试并打开共享停机信号；其他队列保留在途响应，停止后续新调用。
   至少等待五分钟后再检查，避免每条队列各自快速重试。
5. 已完成的调用按原响应回放，旧预测内容与原始延迟保持；进度显示使用已落盘条数，避免回放时进度倒退。
6. 所有 1500 条预测完成后才统一评分、核验、绘图和生成报告。恢复期间不查看测试成绩。

## 预算和停止条件

- 项目停止线仍为 180 元，每个条件仍为 20 元。
- 自动恢复最多观察 24 小时；新增失败及在途预留合计最多 5 元，跨进程加锁检查。
  成功请求按 usage 回填，旧失败费用预留不释放；因此这个上限不是声称额外实付了 5 元。
- 运行状态保存在忽略的 `results/repro/stage3-auto-resume-status.json`；日志为
  `results/repro/stage3-auto-resume.console.log`。状态持续有心跳，包含下次检测时间。
- 用户可双击 `repro/停止自动续跑.command` 请求停止后续检测和新调用；已经在途的请求允许先返回，
  避免人为丢失结果。关闭“查看实验进度”窗口只退出监控。

```bash
# 首次运行前封存恢复适配器（不调用 API）
.venv/bin/python -m repro.auto_resume --seal
# 开启定时检查及有预算约束的续跑；单实例锁阻止重复启动
.venv/bin/python -m repro.auto_resume
# 请求停止；等待当前响应返回，不新增模型请求
.venv/bin/python -m repro.auto_resume --stop
# 明确重新启用此前手动停止的恢复任务
.venv/bin/python -m repro.auto_resume --resume
```
